# Основания первого пути — 17 октября 2026

Проверены официальные источники; реальные подключения не выполнялись.

| Решение макета | Основание |
|---|---|
| Входящий вебхук; права владельца и выбранных областей; необходимость REST-доступа | [Вебхуки Битрикс24](https://apidocs.bitrix24.com/local-integrations/local-webhooks.html) |
| Создание лида, название, имя, контактные данные, ответственный, источник и стадия | [crm.item.add](https://apidocs.bitrix24.com/api-reference/crm/universal/crm-item-add.html) |
| Схема полей зависит от портала; обязательные поля нельзя считать фиксированными | [crm.item.fields](https://apidocs.bitrix24.com/api-reference/crm/universal/crm-item-fields.html) |
| Стадии и источники берутся из справочников | [crm.status.list](https://apidocs.bitrix24.ru/api-reference/crm/status/crm-status-list.html) |
| Контакты и сделки amoCRM как назначение сервиса в каталоге | [Контакты amoCRM](https://www.amocrm.ru/developers/content/crm_platform/contacts-api) |
| Mindbox предоставляет настроенные операции проекта | [Документация операций Mindbox](https://developers.mindbox.ru/docs/javascript-1) |

Старый метод crm.lead.add отмечен поставщиком как deprecated, поэтому техническое основание создания — универсальный crm.item.add с типом Lead. Названия методов не выводятся в продуктовый UI.

Входящий вебхук выбран для конкретного демонстрируемого пути. Это не решение исключить OAuth, локальное или тиражное приложение. Для такого пути нужно отдельно спроектировать установку и жизненный цикл приложения; его существование и публикация не предполагаются.

Пример сценария: ручной запуск из доступного диалога, создание лида и сохранение связи. Это предложение Chatballs по SPEC-0037 R-6/R-8/R-10/R-23, а не готовый сценарий, поставляемый Битрикс24. Условие наличия контакта и проверка существующей связи — также предложение этого baseline. Совпадение телефона/почты не используется для автоматического слияния клиентов.

Успех чтения полей не доказывает разрешение на запись. При реализации нужны проверки прав, обязательных полей портала и обработка отказа при выполнении. Проверка подключения не должна создавать пробный лид. Повтор при неизвестном результате требует сверки, а не обещания идемпотентности API Битрикс24.

Пример не обещает доступность лидов на любом портале: J13 показывает несовместимость. Имена сотрудников, название портала, стадия и источник в кадрах — данные дизайна. Они не получены из установленного адаптера или действующего аккаунта.

## amoCRM и Mindbox

- [Авторизация amoCRM](https://www.amocrm.ru/developers/content/oauth/step-by-step): OAuth и долгосрочные токены приватных/внешних интеграций, срок и отзыв. [Разрешения](https://www.amocrm.ru/developers/content/oauth/scopes): первоначальный доступ администратора. Q01–Q03 предполагают настроенное приложение установки; Q11 явно показывает его отсутствие. Способ регистрации/публикации приложения не утверждается этим макетом.
- [Сделки amoCRM](https://www.amocrm.ru/developers/content/crm_platform/leads-api): название, воронка/этап, ответственный, привязка контакта. Пресет и проверка сохранённой связи — предложение Chatballs; названия справочников в кадре иллюстративные.
- [Операции Mindbox](https://developers.mindbox.ru/docs/javascript-1): адрес API, точка интеграции, секретный ключ и получение клиента; [настройка операций](https://developers.mindbox.ru/docs/userregxml) зависит от проекта. Макет не обещает автоматическое обнаружение или одинаковые операции во всех проектах. Описание операции чтения должно быть предоставлено интеграцией; если его нет, D09 блокирует проверку и включение. Успешный переход в D04 — кадр просмотра, не доказательство внешнего доступа.
- Чтение клиента Mindbox может содержать персональные данные: выбор допустимой операции/полей и полномочий должен соблюдаться в реализации. Для просмотра вводятся только вымышленные значения, API-запросы отсутствуют.
