## Повторяемые команды

Из корня checkout:

```powershell
node design/baseline/service-integrations/build-runtime.mjs
node design/baseline/service-integrations/build-baseline.mjs --preview journey
node design/baseline/service-integrations/check-browser.mjs
git diff --check
```

Первая команда собирает автономные ресурсы макета из 136 исходных модулей workspace. Вторая проверяет синтаксис, локальные ресурсы, уникальность кадров, формат x-dc/canvas и размер исходных файлов; генерирует остальные HTML-входы и файл загрузки для Playwright. Третья запускает только девять проверок этого baseline и открытие четырёх HTML-файлов в установленном Chrome. Сборка приложения и полный прогон тестов не запускались.

Каждый checks/*.playwright.js можно также выполнить task-local Playwright Skaro после generated/open.playwright.js. editor-ui выполняется после custom: он проверяет заполненный редактор. Файл загрузки генерируется локально, игнорируется Git; HTTP-сервер для него не нужен.

## Штатный проект и визуальная проверка

Среда T-166 запущена через start_environment Skaro. Backend приложения/платформы, PostgreSQL и Redis проверены штатным compose ps; frontend использует backend-app:8000. Существующий демо-администратор проверен чтением базы, затем выполнен вход существующими реквизитами. Seed, сброс паролей, изменение ролей и подменяющие API не использовались.

В штатном приложении просмотрен существующий раздел интеграций. С ним сверены навигация, доступные разделы настроек, поверхность рабочей области, вкладки и метрики: sidebar 220/60 px, subnav 240 px, padding 28/40/48 px, заголовок 20 px. Браузерная проверка новой композиции выполнена отдельно как проверка дизайн-документа, без исполнения интеграций.

Визуально просмотрены каталог и список подключений, заполненный редактор, форма действия, параметры и состояния; 1024/1440, светлая/тёмная темы. Дополнительно проверен тёмный кадр загрузки с общим индикатором. Последняя проверка консоли task-local Playwright: 0 ошибок и предупреждений.

## Границы

Реальные OAuth, чтение/запись сервисов, хранение секретов, runtime прав, планировщик и исполнитель не реализованы и не проверялись этим baseline. Принимаются структура и взаимодействия будущего UI. Все соответствующие элементы C4 остаются planned.

Максимальный исходный файл — 84 строки; композиция, модели, словари, формы и проверки разделены. Сгенерированные зависимости не редактируются вручную. Продуктовые файлы и .skaro не изменялись.

Все относящиеся кадры и новые композиции ожидают личного решения владельца. Автоматические проверки не означают, что задача принята или завершена.
