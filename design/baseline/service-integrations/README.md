- [Сервисы](Сервисы.dc.html): каталог, подключение, доступ/восстановление, карточка, пресеты, настройка обмена каждой пары и направлений статусов.
- [Сценарии](Сценарии.dc.html): «Запуск → Условия → Шаги», составные блоки, поля/перебор/ошибки, входы вложенных сценариев, расписание и внешний ключ.
- [Запуск из диалога](Запуск%20из%20диалога.dc.html): поиск/выбор/замена связи, параметры, выполнение, подтверждения, проверочный и мобильный чат.

- [Структура настроек](Настройки%20·%20структура.dc.html): принят вариант 1b, группы с подписями; экраны не объединяются.

- [Импорт, согласованное дополнение и проверки](IMPORT-2026-10-22.md).

## Перенос в продукт

Точная структура, компоненты и состояния сохраняются. Подставляются реальные
схемы/справочники штатного API; бренды, ключи и данные примеров не хардкодятся.
Для каждого направления обмена задаётся своя таблица. Несопоставленное
значение («Не менять») сохраняет статус получателя.

Упрощённая проверка обязательного входа в интерактивном макете не является
требованием продукта: пустое обязательное значение/неверная привязка должны
блокировать включение. Новый макет ради исправления проверки не нужен.

Готовность и распределение по существующим T-168–T-176 описаны в
SPEC-0037 и docs/service-integrations-implementation-readiness.md Skaro.
Пакет документации/C4 применяется после решения владельца в карточке.
Задачи/их границы/зависимости не пересоздаются. Брендовые адаптеры следуют
отдельными реализациями; общий механизм не выдаётся за готовую CRM-интеграцию.

Браузерная проверка компоновки пока не выполнена — инструмент недоступен.
Статические проверки и принятое владельцем содержимое не заменяют browser-
проверку реализации в штатном контуре. Прежние протоколы VERIFICATION.md и
T167-VERIFICATION.md относятся к предыдущим импортам.
