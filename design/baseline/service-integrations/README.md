# Подключение сервисов и редактор сценариев — на просмотр владельцу

Текущая итерация подготовлена после отклонения предыдущих результатов. Личная приёмка ещё не получена.

Открыть [journey.dc.html](journey.dc.html). Все четыре HTML-входа показывают один baseline: connections.dc.html начинает со списка сервисов, editor.dc.html — с редактора, settings.dc.html — с хранения. Старая отдельная версия редактора больше не открывается из этих файлов.

Это интерактивный дизайн-документ в формате x-dc/canvas с существующим support.js. Подключения, справочники и события в нём — иллюстрации. Данные живут в памяти вкладки, запросов к сервисам и исполнения действий нет. Подсказка об этом находится над продуктовым кадром. Для просмотра вводить только вымышленные секреты.

## Как просматривать

1. **Битрикс24:** начать с каталога → подключить → название и ссылка https://nord.example/rest/1/preview/ → проверить и подключить → готовый сценарий → выбрать ответственного → проверить → включить → изменить сценарий. Откроется общий редактор с двумя шагами: создать лид и связать его с диалогом.
2. **Свой сценарий:** карточка сервиса → создать свой → название → добавить шаг → действие → подключение → действие → откуда взять значение. Пример: название лида из темы диалога. Следующим шагом можно связать запись с диалогом, выбрав результат первого шага.
3. **Редактирование:** шаги переносятся за маркер слева; показаны тень и место вставки. Esc отменяет перенос, стрелки на клавиатуре переставляют сфокусированный шаг. Настройка — отдельная кнопка, копирование и удаление — штатное меню строки.
4. **Расширенные возможности:** при добавлении шага открыть «Условия, ожидания и другие блоки». Для ветвления, перебора, параллельных ветвей и обработки ошибки действия добавляются внутрь соответствующей ветви.
5. **Запуск и доступ:** включить нужные способы. Доступны сотрудник, ИИ, события Chatballs и сервиса, расписание, внешний API и другой сценарий. Автоматический запуск требует явного делегирования; режим ИИ задаётся отдельно.
6. **Параметры:** добавить входные поля и результаты; доступны вложенные объекты, списки, даты, справочники и файлы. Разрешённые значения редактируются отдельным списком. Объекты и списки собираются полями без JSON. У преобразований настраиваются разделитель, часовой пояс, поля объекта или условие отбора элементов.
7. **Связи и обмен:** выбрать записи и подключение; включить обмен только при необходимости. Настраиваются соответствия, направление, главный источник, конфликты и удаление.
8. **amoCRM:** каталог → OAuth или токен. Исход возврата OAuth выбирается над макетом. Затем подтверждение аккаунта, настройка сделки и включение. Редактирование включённой копии ведёт в тот же редактор.
9. **Mindbox:** подключение с вымышленным ключом → сохранение без проверки → безопасное чтение существующего клиента → готовый сценарий. Если безопасной проверки нет, используется соответствующее состояние, без записи ради теста.
10. **Повторное подключение:** J11 → «Ещё одно подключение Битрикс24». После заполнения J10 показывает две независимые строки. Настройки готовых сценариев и сохранённые собственные сценарии относятся к выбранному подключению.
11. **Хранение:** Y15, по умолчанию 7/30 дней после завершения. Сокращение сроков открывает существующий DecisionDialog; отмена не применяет настройку.

Сохранение черновика, проверка и включение разделены. Выход с изменениями требует решения; включённая версия продолжает работать до явного включения новой. Конфликт редактирования не перезаписывается молча.

## Карта кадров

| Кадры | Что проверить |
|---|---|
| J01–J06 | Каталог, Битрикс24, готовый сценарий, проверка и включение |
| J10–J13 | Список, несколько подключений, доступ, ошибки CRM |
| Q01–Q11 | amoCRM: OAuth/токен, возвраты, восстановление, сценарий сделки |
| D01–D10 | Mindbox: ключ, безопасная проверка, отсутствие проверки, сценарий чтения |
| X01–X03 | Общий редактор, выбор шага, действие и значения |
| X04–X05 | Группы условий; все виды составных блоков и ожиданий |
| X06–X09 | Проверка, версии, семь способов запуска, несохранённые правки |
| X10–X12 | Вход/выход, связи/синхронизация и решение конфликта |
| Y01–Y08 | Пустые, ошибочные, недоступные, выключенные состояния и права |
| Y09–Y14 | Конкурентные правки, сохранение, зависимости удаления, справочник и файл |
| Y15 | Хранение 7/30, изменение и подтверждение |
| Y16 | Загрузка каталога штатным индикатором; размер области совпадает с готовностью, ошибкой и пустым результатом |
| Z01–Z06 | Контролы объявленных способов доступа: ключ, Bearer, Basic, подпись, сертификат, специфические поля |

Z-кадры показывают формы схем доступа адаптера. Они не утверждают, что каждый из трёх брендов поддерживает все способы. Каталог текущего пути показывает примеры сервисов; реальный каталог будущего приложения должен строиться только из установленных адаптеров. J07–J09 заменены общим редактором X01–X05.

## Существующие компоненты и оформление

runtime.tsx импортирует компоненты этого checkout, product-styles.ts — их исходные стили. build-runtime.mjs собирает автономные ресурсы из 136 исходных модулей workspace, без запуска приложения или сетевых hooks.

| Область | Источник |
|---|---|
| Навигация и настройки | SidebarNavigation, OrganizationSwitcher, NavigationIcon, SETTINGS_SECTIONS; layout и settings/styles.css |
| Поля и переключатели | shared/form-controls: FormField, SelectField, TextAreaField, SwitchButton |
| Кнопки, ссылки, вкладки | shared/ui-controls: Button, UnderlineTabs, BackLink, SearchInput; shared/links.css; integrations-tabs |
| Меню | antd Dropdown, app-dropdown, row-menu-button; образец ParameterRow и CustomFieldRow |
| Перенос | существующие grip и клавиатурное управление CustomFieldRow; тень shadow-lg и акцентные токены |
| Подтверждения | исходный DecisionDialog; CanvasDialog лишь помещает портал внутрь кадра |
| Таблицы и состояния | baseline-table/table-card; ContentState, LoadingState, StatusPill; существующие цвета статусов |
| Метрики | settings: 28/40/48 px, заголовок 20 px, кнопки 34 px; поля 320 px, длинные 480 px, числа 160 px; значение 320 px взято из узких полей настроек портала |

Все цвета берутся из темы и системного акцента. Фон рабочей области — surface-feed, карточки — surface-card. Настройки не получили новой шапки или хлебных крошек. Действия таблиц выровнены справа, вспомогательные ссылки используют is-muted. Ненужные разделители строк убраны.

Логотипы — предоставленные владельцем SVG: Битрикс24 цветной/белый, Mindbox чёрный/белый, amoCRM из amocrm-logo-white_2.svg с сохранением контуров и цветов. Один ServiceLogo используется во всех соответствующих местах.

## Новые переиспользуемые композиции для личной приёмки

CustomSteps — список шагов с переносом, вставкой и меню; BindingEditor — источники, поля результата и преобразования; Transformation.Settings — параметры преобразования; ParameterChoices — разрешённые значения; ConstantValues — объекты/списки без кода; SchemaEditor — входные/выходные схемы; ConditionEditor — группы И/ИЛИ; LaunchSettings — способы запуска и делегирование; SyncSettings — связи и обмен; Access — формы способов доступа; CatalogSurface — общая область состояний каталога.

Они разделены на компоненты, словари и модель состояния. Самый большой исходный файл — 84 строки. Сгенерированные зависимости не редактируются вручную.

## Границы результата

Это baseline T-166, без backend, API, исполнителя, адаптеров или продуктового UI. Все соответствующие элементы C4 остаются planned. Внутренний каталог показывает группы публичных действий и примеры выбора; исчерпывающее соответствие API и реестра действий проверяется при реализации этапа, а не объявляется выполненным этим макетом. Журнал и рабочий запуск из чата относятся к соседнему baseline.

Старые JS-модули прежней концепции сохранены как исторические исходники; текущие HTML их не загружают. Источник текущей композиции — journey.dc.html и подключённые им модули. Личная приёмка всех относящихся кадров и новых компонентов обязательна перед реализацией.
