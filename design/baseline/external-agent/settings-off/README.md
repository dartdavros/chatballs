# S01 — внешнее исполнение выключено

Экран **S01-r2, Настройки → Обслуживание → Внешнее исполнение, возможность выключена**, лично принят владельцем 15.11.2026 для версии `S01-5037b71a01f54b2b`. Запись решения — `OWNER-ACCEPTANCE.md`. Этот документ открывает только принятый S01; включённое состояние готовится отдельно как S02.

`settings.dc.html` открывается непосредственно в браузере по умолчанию. Исходники редактируются в соседних TSX/TS-файлах. Это статический дизайн с примерным содержимым, без приложения, backend, API, mock API, временного HTTP-сервера, seed или реального внешнего сервиса. Сохранение, изменение статуса и переходы не выполняются. Переключатель остаётся выключенным, чтобы не показывать второй непринятый кадр; это ограничение просмотра, а не предлагаемое продуктовое поведение.

## Что предъявляется на утверждение

- По указанию владельца добавлен последний пункт **«Внешнее исполнение»** в группе **«Обслуживание»** субменю настроек. Используется существующая иконка **server** из `shared/icons.tsx`. Все остальные пункты и их порядок сохранены; основная навигация не меняется.
- Открывается отдельный раздел настроек с карточкой внешнего исполнения. Форма организации и настройка хранения истории сценариев здесь не отображаются. Прежнее размещение S01-r1 отклонено владельцем.
- Используется текущая карточка настроек с заголовком, подписью и общим переключателем, по образцу `ToolsNetworkCard`. Внешнее исполнение выключено по умолчанию.
- Форма подключения, адрес, ключи, идентификаторы и проверка сервиса в выключенном состоянии скрыты. После включения их настройка должна появиться здесь же; её дизайн относится к следующему проходу после решения владельца.
- Подсказка объясняет появление выбора исполнения в карточках агентов. Включение возможности не переключает существующих агентов автоматически.
- Новые тексты ru/en являются предложением (`copy.ts`). Продуктовые словари не менялись. Компоненты и токены взяты из актуального кода; старые макеты не использованы как визуальный источник.

CSS документа оформляет только инструменты просмотра вне продуктового кадра и размер рамки. Внутри используются стили приложения. Для проверяемой ширины media queries компилируются в container queries; мобильные классы совпадают с текущим `SettingsPage`. Применяется существующее исключение `.hub-shell.is-settings-route` для ширин до 900 px, скрытие субменю и кнопка возврата. Существующие ограничения соседних компонентов фиксируются в протоколе; новый мобильный интерфейс не проектируется.

## Проверка и версия

`node design/baseline/external-agent/settings-off/build.mjs` собирает только ресурсы дизайна, проверяет ru/en, ключи и размеры авторских файлов. Сборка приложения не выполняется.

`node design/baseline/external-agent/settings-off/check-browser.mjs` проверяет единственный S01 в установленном Chrome по native file URL: темы, языки, ширины, акценты, выключенный переключатель, отсутствие формы подключения и сетевых запросов. Масштаб 200% проверяется как CSS-масштаб просмотра; это не заявление о проверке нативного zoom браузера.

Точная версия и SHA-256 исходников — `generated/sources.json`. Скриншоты и протокол — `verification/`. Решение владельца фиксируется отдельно в `OWNER-ACCEPTANCE.md`; подготовка файлов и браузерная проверка не означают приёмки дизайна или работоспособности интеграции.
