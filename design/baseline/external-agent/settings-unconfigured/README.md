# S02 — включено, подключение ещё не настроено

Экран **S02-r1, Настройки → Обслуживание → Внешнее исполнение**, лично принят владельцем 15.11.2026 для версии `S02-c8d1b152d7078f85`. Возможность включена, но подключения ещё нет. Решение — `OWNER-ACCEPTANCE.md`. Этот документ открывает только принятый S02; готовое подключение готовится отдельно как S03.

Открыть `settings.dc.html` непосредственно в браузере по умолчанию. Это статический дизайн, не приложение или проверка интеграции. API, backend, внешние сервисы, временные серверы, mock API, seed и реальные ключи не используются. На этом проходе не показываются другие состояния.

## Предложение для приёмки

- Включённый общий переключатель не означает готовности сервиса и не меняет исполнение ранее настроенных агентов автоматически.
- Под ним — пустая встроенная форма подключения: название, HTTPS-адрес и исходящий ключ **Chatballs → внешний сервис**. Секретное поле пустое, без точек и признака сохранённого ключа.
- Направление **внешний сервис → Chatballs** отделено. Ключ ещё не создан. Показана явная кнопка «Создать ключ» и правило однократного показа нового ключа; реальный ключ не создаётся и не раскрывается.
- Конкретное размещение действия создания ключа предъявляется как предложение дизайна. Этот кадр не определяет порядок создания ключа относительно сохранения подключения, не вводит management API и не показывает результат действия.
- Проверка подключения находится у исходящего доступа и пока недоступна, поскольку адрес и ключ не заполнены. Она читает возможности сервиса, не запускает диалог или модель. Сохранение пустого подключения также недоступно. Статус нейтральный: «Не настроено».
- Параметры обработки, внешние идентификаторы и привязки, разрешения данных и шаблонов остаются в этом разделе настроек; их последующие состояния не считаются реализованными данным начальным кадром.

Переключатель, поля и создание ключа не меняют показанный статический кадр. Сохранение, проверка и переходы не выполняются. Это ограничение просмотра одного состояния, а не продуктовое поведение. Не вводить реальные ключи.

Точная версия — `generated/sources.json`, протокол и снимки — `verification/`, решение владельца — `OWNER-ACCEPTANCE.md`. Включённый переключатель в макете не меняет настройки реальной организации.
