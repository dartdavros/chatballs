# Диктовка и прослушивание ответов — baseline

Лично принято владельцем 04.11.2026 после исправлений. Это статический дизайн-артефакт, продуктовый UI речи не реализован. Приёмка задачи, спецификации или архитектуры не заменяет личную приёмку этих макетов. Её отдельная запись с решением и принятым коммитом — [OWNER-ACCEPTANCE.md](OWNER-ACCEPTANCE.md).

Открывайте файлы непосредственно в браузере, сохраняя соседние ресурсы:

- [settings.dc.html](settings.dc.html) — SpeechKit, агент, WEB и обязательная форма.
- [dictation.dc.html](dictation.dc.html) — диктовка, черновик, ошибки и прежние голосовые.
- [playback.dc.html](playback.dc.html) — проигрыватель окончательного AI-ответа.

Над кадром находятся **инструменты просмотра макета**, не часть продукта: выбор состояния, языка, ширины, темы и акцента. Можно показать все кадры раздела. Длинные настройки и переписка прокручиваются внутри рамки. Полные исходные снимки и нижние части — в [verification/](verification/); контактные листы дают быстрый обзор.

В макете нет реальной записи, звука, распознавания, синтеза, API, backend или запросов к провайдеру. Значения подключений, моделей и голоса — примеры для проверки компоновки; реальный каталог предоставляет адаптер. Не вводите настоящие ключи. Состояния ошибок выбираются над кадром, а не получаются от сервиса. Кнопки вне проверяемого речевого сценария сохранены как контекст и не запускают продуктовые действия.

## Как посмотреть взаимодействия

Диктовка: D01 → «Продиктовать сообщение» (микрофон) → разрешение. До нажатия микрофона статуса и пустого места под него нет. Компактный статус появляется над полем ввода. Кнопка просмотра «Следующее состояние» показывает разрешённую запись; сплошной квадрат «Остановить» без подложки показывает распознавание. Крестик без фона отменяет действие. В ожидании можно печатать. «Показать результат распознавания» добавляет пример к текущему черновику ровно один раз. Отмена и запоздавший результат не меняют черновик. Только явная отправка добавляет иллюстрацию обычного текстового сообщения. Enter отправляет, Shift+Enter переносит строку, Escape отменяет диктовку.

Прослушивание: в правом нижнем углу AI-сообщения находится Lucide Volume2. Плеер скрыт до нажатия этой кнопки; после нажатия он появляется внутри того же пузыря, а Volume2 заменяется на Square. Нажатие Square останавливает звук, скрывает плеер и возвращает Volume2. «Следующее состояние» иллюстрирует готовый звук, круглая кнопка плеера — паузу/продолжение/повтор. В P13 запуск второго ответа останавливает и скрывает первый плеер; микрофон останавливает и скрывает проигрыватель. Это проверка визуального сценария, не аудиодвижка.

В SpeechKit поля названия и каталога стоят в одной строке равными колонками, ключ занимает всю их ширину. Использованы карточка и сетка OrganizationSettingsForm (`administration-card`, `administration-fields`, `administration-field-wide`), действия и блок ошибок настроек из того же раздела. У форм нет собственных ограничений 320/180/640 px: одиночные поля WEB занимают ширину штатной карточки, лимиты объединены в `server-two-fields` с переходом в одну колонку на мобильном. Ошибки полей выводит FormField, ошибка выбранного подключения использует `integration-form-error`. Проверки возможностей выровнены по колонкам. Сообщения «Изменения сохранены» и отдельного пустого места для него нет — сохранено поведение штатного WebIntegrationBasics.

runtime.tsx собирает только презентационные компоненты checkout; App, авторизация, продуктовые data loaders и речевые API не монтируются. generated/sources.json содержит точный список исходников сборки. Код документа, словари, состояния, композиция, проигрыватель и проверки разделены по файлам; authored-файлов больше 300 строк нет. Сгенерированный бандл не является authored-компонентом.

Ревизия по замечаниям владельца от 04.11.2026 заменяет предыдущую композицию проигрывателя и постоянный высокий блок диктовки. Исправленный baseline лично принят владельцем. Обычный composer повторяет размеры ChatComposer: одна строка с ростом до 132 px. Уточнение T-182 от 05.11.2026: активный статус диктовки имеет высоту по содержимому с минимумом 36 px над вводом, штатную типографику 15/21 px, акцентный стоп 36 px и интервал микрофон–отправка 8 px; крестик полностью скрывает панель. Открытый проигрыватель использует штатную волну и круглую кнопку. Явное открытие/закрытие области меняет размер пузыря/композера по указанию владельца; загрузка/ошибка/пауза внутри открытой области сохраняют её геометрию. Отдельных продуктовых экранов/меню и нового стиля ссылок нет. Встроенный виджет сохраняет исходную светлую палитру независимо от темы рабочего места. Настройки прокручиваются, остальные существующие колонки на мобильном складываются. Пример кода вставки использует `chat.example`, поскольку статический документ не имеет адреса развёрнутого приложения.

## Проверка и пересборка

Из корня checkout, при Node и Git в PATH:

```powershell
node design/baseline/widget-speech/build.mjs
node design/baseline/widget-speech/check-browser.mjs
```

Используются существующие зависимости проекта и Chrome в отдельном чистом профиле. Для зависимости в другом месте предусмотрен BASELINE_NODE_MODULES. Ни сервер, ни сервисы приложения не запускаются. Первый скрипт собирает автономные JS/CSS и три .dc.html, проверяет синтаксис, ресурсы, совпадение ru/en и размер authored-файлов. Второй открывает настоящие file:// документы, проверяет матрицу, взаимодействия и масштаб, сохраняет снимки/JSON.

Для task-local Playwright, блокирующего file://, build.mjs создаёт ignored `generated/open-{settings,dictation,playback}.playwright.js`: он передаёт те же локальные ресурсы через page.setContent на about:blank. Это статический документ, без HTTP-сервера или подмены API. Затем запускаются `checks/*.playwright.js`.

Подробный журнал — [VERIFICATION.md](VERIFICATION.md). Проверка реального SpeechKit и штатного продуктового UI относится к следующим задачам этапа и здесь не объявляется выполненной.
