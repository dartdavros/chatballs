# Каналы обработки — design baseline (DG-02)

Макет раздела **Компания → Каналы** (CustoCRM / ООО «Эдевс») по SPEC-HUB-0027 / ADR-HUB-0037.

## Состав

```
Каналы Baseline.dc.html               — макет (6 кадров: A–E + состояния)
support.js                            — рантайм Design Component (шаблон + логика)
_ds/edevs-hub-design-system-…/        — дизайн-система: токены, styles.css, _ds_bundle.js
assets/custocrm-mark.svg              — логотип CustoCRM
```

## Запуск

Открыть `Каналы Baseline.dc.html` через локальный HTTP-сервер
(из-за загрузки внешних файлов `file://` не подойдёт):

```bash
python3 -m http.server 8080
# → http://localhost:8080/Каналы%20Baseline.dc.html
```

## Карта кадров (SPEC-HUB-0027 §11.6)

- **A** — Список каналов: полная оболочка (sidebar + topbar). Фильтры-`UnderlineTabs` с count
  (`Все · Продажи · Поддержка · Без отдела`), поиск, тумблер «Показывать архивные».
  Плотная `baseline-table` в `table-card`. Колонки `КАНАЛ / ПРОДУКТ / ПОДКЛЮЧЕНИЯ /
  AI-АГЕНТ / ДИАЛОГИ / ⋯`. Показано открытое меню строки с заблокированным «Удалить»
  и причиной. §11.1.
- **B** — Карточка канала **одной страницей, без вкладок**. Заголовок (`code · отдел ·
  продукт`, действия «Изменить / Деактивировать / Удалить») и секции сверху вниз:
  Назначение, Политика, Подключения, AI-агент (одна строка: имя · статус · модель +
  ссылка «Открыть агента» на страницу агента наружу), Счётчики (открытые диалоги,
  подключения + ссылка на диалоги). Настроек агента и знаний в карточке нет. §11.2.
- **C** — Секция «Политика» на **непродуктовом** канале «Партнёрская линия».
  Пять флагов с однострочным пояснением следствия; три флага (checkout P1,
  attribution P2, обязательная идентичность P3) выключены и заблокированы с причиной. §11.2.
- **D** — Секция «Подключения». Список подключений канала с отвязкой, действие
  «Привязать» и модалка **переноса** подключения из другого канала (`force`),
  с оговоркой, что диалоги остаются в прежнем канале. §11.1 / §6.6.
- **E** — Мастер создания, **три шага** (Канал · Назначение · Подключения). Показан
  финальный экран: канал создан, ведут его операторы, ссылка в раздел AI для создания
  агента отдельным действием. Настроек агента и знаний в мастере нет. §11.3.
- **S** — Состояния: пустой список (приглашение без «здесь пусто»), канал без агента
  (секция AI-агент), архивный канал, ограниченный доступ (department scope), конфликт
  удаления (409 с блокерами). §11.5 / §7.2.

## Зафиксированные решения по открытым вопросам (README §5 задания)

1. **Канал без отдела.** В колонке `КАНАЛ` под именем идёт `code · <чип «Без отдела»>` —
   нейтральный чип на `--n-9`, а не пустая ячейка: канал читается как намеренно
   безотдельный, а не как незаполненный черновик. Плюс отдельный таб-фильтр «Без отдела».
   Такой канал виден только organization-scoped `channels.view` (§5.2).
2. **Архивный канал (`isActive=false`).** Отдельный статус `Архивный` (полая точка,
   приглушённый текст, фон строки `#fcfcfc`), а не «Выключено». По умолчанию скрыт,
   показывается тумблером «Показывать архивные». Меню строки предлагает только
   «Активировать». История диалогов сохраняется и доступна ссылкой из карточки
   («История сохраняется даже после деактивации канала»).
3. **Запрещённый инвариантом флаг политики.** Флаг выключен **и** заблокирован, рядом —
   бейдж «Запрещено инвариантом» / «Недоступно» и однострочная причина со ссылкой на
   инвариант (P1/P2/P3) и способ разблокировать («Назначить продукт»). Причина
   объясняется, а не игнорируется молча при сохранении. Кадр C, флаг checkout выделен.
4. **Колонка «Диалоги» в списке.** Оставлена. Обоснование: это дешёвый агрегат
   (`counters.openConversations`, один запрос на список, §6.1), а открытые диалоги —
   ключевой операционный сигнал канала. Полный разрез счётчиков (открытые диалоги и
   подключения) остаётся в секции «Счётчики» карточки; в списке — только открытые
   диалоги, numeric. Счётчика знаний в карточке канала нет: знания принадлежат агенту.

## Технические примечания

- Вёрстка — инлайн-стили поверх токенов дизайн-системы (`var(--*)` из `_ds/.../tokens`).
  Цвета/типографика/отступы менять только через токены; сырые hex вне токенов не
  используются (кроме служебного фона холста и подсветок строк из baseline-образца).
- `ChannelBadge` (точка + короткий лейбл MAX/TG/Web на токенах `--channel-*`) применяется
  экономно — только в колонке «Подключения» списка и в секции «Подключения» карточки
  (ADR-HUB-0013).
- Терминология: MAX/TG/Web — «Подключения»; «Канал» — сущность маршрутизации.
- Данные — примеры; авторизация, инварианты и счётчики вычисляются на backend
  (frontend не источник прав), см. SPEC-HUB-0027 §5–§7.
