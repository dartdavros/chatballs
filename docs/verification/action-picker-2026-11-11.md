# Выбор действий, заголовки разделов и поиск

## Объём изменений

Патч подготовлен относительно актуального архива `chatballs(1).zip` и утверждённого интерактивного макета выбора действия. В архиве патча находятся только добавленные и изменённые файлы с путями от корня проекта. Удаление файлов не требуется.

- Заголовок вкладки формируется по текущему разделу: например, `Чаты · Chatballs`. Переключение языка обновляет название раздела.
- Кнопка «Действие» открывает модальное окно с поиском, группами, вложенными категориями, счётчиками и контекстом текущего диалога.
- Сервисные операции группируются по подключению и категориям адаптера. Для Битрикс24 явно заданы категории CRM и пользователей. Разные подключения остаются разными группами.
- Собственные сценарии получают необязательный путь категории. В редакторе используется запись `Продажи / Лиды`; допустимы до трёх уровней и до 80 символов в названии каждого уровня. Сценарии без пути остаются в группе «Без категории». Копирование сохраняет категорию, обновление через старый API без `categoryPath` её не стирает.
- Поиск учитывает названия действий, групп, подключений и категорий. Найденные ветки раскрываются; пустые группы скрываются. Очистка поиска восстанавливает предыдущее раскрытие дерева.
- Параметры действия загружаются после выбора. Выбор открывает существующий процесс подготовки и подтверждения запуска. Сам выбор операцию не запускает.
- Поздние ответы от закрытого окна или предыдущего диалога не меняют текущий выбор. История запусков загружается независимо от каталога действий.
- Во всех полях поиска используется подсказка `/` по образцу поиска чата. Клавиша фокусирует подходящее видимое поле, учитывает открытые модальные окна и не перехватывает ввод в редактируемом поле. При непустом запросе подсказка уступает место очистке, как в исходном поиске чата.

## Доступность и выполнение

Сервер исключает из каталога выключенные и недоступные сотруднику действия, учитывая организацию, диалог, доступ сценария, актуальные разрешения и подключения. Разрешения проверяются повторно при получении параметров, подготовке, запуске и HTTP-повторе запуска. Пользовательский payload не может отключить ручную проверку.

Проверяются условия, которые уже можно определить по текущему контексту и константам. Условия, зависящие от ещё не введённых параметров или будущего контекста дочернего сценария, проверяются на соответствующем этапе выполнения. Нельзя заранее гарантировать успешность внешней операции по одному факту её присутствия в каталоге.

Если запуск отклонён, старое подтверждение инвалидируется и подготовка пересчитывается. Автоматического повторного запуска нет: для выполнения требуется отдельный клик сотрудника.

Добавлены регрессионные проверки недоступных действий, отзыва разрешений, неверного контекста диалога, сохранения категорий и запрета HTTP-повтора составного сценария после отзыва разрешения на последующий шаг. DB-зависимые проверки нужно выполнить в рабочем тестовом окружении проекта.

## Применение локально

1. Распаковать патч в корень проекта, где находятся `package.json` и `compose.yaml`, с заменой файлов. Внутри патча нет дополнительной обёртки `chatballs/`.
2. Установить зависимости по существующему lock-файлу и собрать интерфейс. Манифесты зависимостей этим патчем не изменены.

```powershell
npm ci
npm --workspace @chatballs/internal-ui run build
```

3. Применить новую миграцию `integrations.0034_scenario_category_path` через штатный сервис `init`. Миграция добавляет `category_path` с пустым списком по умолчанию. Одной сборки интерфейса недостаточно.

Для уже работающего основного dev-окружения с `compose.yaml` и `compose.dev.yaml`:

```powershell
$chatballsComposeArgs = @('compose', '-f', 'compose.yaml', '-f', 'compose.dev.yaml')

docker @chatballsComposeArgs build init
if ($LASTEXITCODE -ne 0) { throw 'Не удалось пересобрать образ init.' }

docker @chatballsComposeArgs run --rm --no-deps init
if ($LASTEXITCODE -ne 0) { throw 'Миграции завершились ошибкой.' }

docker @chatballsComposeArgs restart backend-app backend-platform worker worker-events
if ($LASTEXITCODE -ne 0) { throw 'Не удалось перезапустить сервисы приложения.' }
```

`init` нужно пересобрать: у него нет монтирования исходников backend, и старая версия образа не содержит новый файл миграции. `run --no-deps` предполагает уже работающие зависимости текущего dev-окружения. Следует сохранить используемые ранее имя Compose-проекта, переменные, каталоги данных и дополнительные override-файлы, в том числе `compose.task.yaml`, если это task-окружение.

Не запускать `migrate` в `backend-app`: сервис работает с ролью БД приложения; для изменения схемы проект использует роль миграции в `init`. Эти команды описывают локальное dev-окружение, а не перенос или переустройство production.

После успешного применения обновить страницу приложения. Категории существующих сценариев можно заполнить в их редакторе.
