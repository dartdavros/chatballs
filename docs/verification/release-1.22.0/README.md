# Проверки перед выпуском Chatballs 1.22.0

Дата: 2026-11-16.

## Результат

- **201 backend-тест** выбранной области выполнен успешно в последовательных адресных прогонах: 147 + 6 + 19 + 29. Состав проверен повторной коллекцией pytest: пропусков и пересечений нет. Подробности и идентификаторы проверок — [backend-scope.json](backend-scope.json).
- **36 frontend-тестов**, 8 файлов: настройки внешнего исполнения, карточка агента, проверочный чат, отображение состояния сообщений, каталог подключений и i18n.
- **29 тестов CLI и релизного Compose** в Linux; один пропуск для явно разрешённого bind mount Docker-сокета у updater. Предшествующая попытка в Windows выявила отсутствие `sh`; её результаты не выдаются за успешную проверку Linux-скриптов.
- Ruff с корневым `pyproject.toml` — без замечаний. Исправлены три устаревшие проверки типов и порядок импортов в двух тестах.
- TypeScript и production-сборка internal-ui — успешно. Vite сообщил о крупных чанках.
- `manage.py check`, `makemigrations --check --dry-run`, `migrate --check` — успешно; новые миграции ради исправлений выпуска не создавались.
- Штатный backend readiness подтвердил доступность PostgreSQL и Redis.
- Браузерная сверка UI описана в [отчёте о настройках](../external-settings-design/README.md).

## Найденные и устранённые проблемы

В `voice.run_voice` запрос с `select_for_update()` и nullable-связью `trigger` отклонялся PostgreSQL. Запрос теперь блокирует саму запись исполнения через `of=("self",)`, как остальные переходы этого модуля. Сохранены блокировка диалога и повторная проверка полномочий. Все шесть голосовых сценариев прошли, включая отзыв управления до вызова STT, отказ провайдера и повторное использование сохранённого распознавания.

Миграционный тест использовал историческую модель интеграции поверх схемы с более новой независимой миграцией. Его исходная граница теперь явно включает `integrations.0035_integration_openai_provider`. Сохранены все проверки встроенного агента, истории, настроек и секрета. Production-миграции для этого не менялись.

`test_scope.py` и `test_views.py` содержат продуктовые функции и API проверочного чата. Они явно отмечены `__test__ = False`. Ошибочно собранная служебная функция `test_route(conversation)` исключена из коллекции; все три настоящих сценария `test_test_scope.py` остаются в проверенном наборе. Никакие реальные тесты не отключались.

## Среда и достоверность

Использовались существующие Compose-сервисы проекта, реальные PostgreSQL/Redis и изолированная тестовая база pytest с `--reuse-db`. Полный набор тестов проекта и `--create-db` не запускались. Учётные данные рабочей базы, роли сотрудников и демо-набор не сбрасывались.

Первый прогон прерван из-за восстановления PostgreSQL после переполнения C:. После отдельного разрешения владельца перезапущен Docker Desktop и удалён только неиспользуемый кеш сборки — 9,832 ГБ. Тома и образы не удалялись. Готовность PostgreSQL и штатного backend подтверждена после восстановления.

Первые 147 тестов прошли из основной копии. Чтобы уменьшить задержки Windows bind mount при последующих проверках, внутри того же backend-контейнера подготовлена копия исходников на Linux-файловой системе. Сверены байты и SHA-256 всех 2268 скопированных файлов backend и контрактов. При исправлениях обновлялись исходник, соответствующая копия и манифест. Итоговый SHA-256 манифеста: `42b5186e736b3615c670d052703a2115412ed563ae85ee5a12c862e1610f079c`.

Сравнение конфигураций исходной копии и снимка подтвердило одинаковые настройки БД, Redis и ключ приложения. Настройки работающего приложения не менялись. Тесты продолжили использовать те же PostgreSQL и Redis; переносилось только расположение проверяемых файлов. Проверка UI выполнена в обычном штатном приложении, её результаты не подменялись результатами этого снимка.

## Границы проверки

Реальные обращения к внешнему исполнителю, OpenAI/STT и всем клиентским каналам отдельно не выполнялись. Обновление копии пользовательской production-базы с 1.21.0 не проверялось. Для браузерной сверки использовалось существующее подключение без привязок; соответствующие ограничения перечислены в UI-отчёте.

Публикация образов и файлов установки проверяется отдельно по фактическому GitHub Actions run и опубликованным артефактам.
