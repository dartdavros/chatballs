# T-185: проверка ручной подстановки

Дата: 06.11.2026. Штатное окружение `skaro-chatballs-t-185`, frontend
`http://localhost:20004`, backend `http://localhost:20002`.
Readiness через frontend подтвердил PostgreSQL и Redis. Миграции выполнены
штатным init; использованы существующие демо-аккаунт и данные копии основной БД.
Секреты, аккаунты, роли и контакты не изменялись. По защищённому вводу владельца
подключён настоящий Битрикс24 через штатную форму; вебхук в артефакты не включён.

## Адресные команды

```sh
docker compose exec -T backend-admin python -m pytest --reuse-db -q chatballs/integrations/adapters/test_initial_values.py chatballs/integrations/adapters/test_schema_registry.py chatballs/integrations/execution/test_manual_initial_values.py chatballs/integrations/execution/test_chat_catalog.py --tb=short
docker compose exec -T frontend npm test -- src/features/integrations/runs/ManualLaunch.test.tsx src/features/integrations/runs/launchFields.test.ts src/features/integrations/runs/ManualActionItem.test.tsx
docker compose exec -T frontend npm run build
docker compose exec -T backend-app python manage.py check
```

Backend покрывает подписи и неизменный ID; регистрацию типизированных привязок;
полные/частичные/пустые данные; вложенные PHONE/EMAIL; другой tenant, скрытый
диалог и заблокированного сотрудника; точные preview/снимок запуска; отсутствие
побочных эффектов каталога и приоритет сохранённого сценария. Backend запускается
только с `--reuse-db`, полного прогона нет. Frontend: 6 тестов, сборка успешна.
Предупреждения сборки о размере существующих чанков не являются ошибками.

## Browser: настоящий backend и портал

Использован task-local Playwright. Проверены существующие диалоги Марии
Соколовой, Ольги Мельник и Дмитрия Орлова. В первых двух известны имя и телефон;
у Дмитрия известное имя, телефон и email отсутствуют. В существующих диалогах
проверенной организации заполненного contact.email нет: его подстановка
проверена адресными backend/SSR-тестами, данные ради демонстрации не создавались.

- Создание лида и контакта сразу показывает известные NAME/PHONE, до preview,
  ошибки или пользовательского ввода. Фамилия, название, стадия и ответственный
  остаются пустыми, неизвестный EMAIL не создаёт строки списка.
- Изменение имени на «Мария — проверка», удаление строки телефона и последующая
  очистка имени передаются в настоящий preview без восстановления defaults.
  HTTP 200: request.parameters и preview.arguments совпадают, включая NAME=""
  и PHONE=[].
- После автоматического GET каталога (HTTP 200) очищенные имя/телефон и выбранный
  ответственный сохраняются. Завершение загрузки справочников ввод не меняет.
- Настоящий user.get показывает `andrey@edevs.tech` вместо ID; выбор передаёт
  `ASSIGNED_BY_ID="1"`. Полное имя/отчество и резерв ID проверены адресным тестом.
- Смена действия на создание контакта заново подставляет исходные сведения.
  Смена диалога на Ольгу использует её телефон, затем Дмитрий не получает чужие
  телефон/email. Форма изменения лида открывается без полей создания.
- Desktop 1440×1000: прежняя правая панель, прокрутка содержимого и закреплённый
  footer. Mobile 390×844: прежний нижний Drawer 88vh, форма прокручивается,
  footer доступен. Проверены light/dark при загрузке приложения в каждой теме;
  document.scrollWidth равен viewport width. Стили, layout и тексты не менялись.
- «Запустить» в браузере не нажимали. Бизнес-записи Битрикс24 не создавались;
  mock API, временные серверы, seed/reset/bootstrap не использовались.

На существующих экранах наблюдались 409 email/options для непочтового диалога
и предупреждения React о повторяющихся ключах списка диалогов. Эти участки
не изменялись; run-actions, его preview и справочники отвечали штатно.
