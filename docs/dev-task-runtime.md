# Постоянное dev-окружение задачи

## Окружение задачи под Skaro (3 октября 2026)

Задачу в собственном worktree обслуживает Skaro по разделу `environment` в
`.skaro/config.yaml`: выдаёт имя Compose-проекта (`skaro-chatballs-<задача>`),
свободные порты и свои теги образов, запускает сервисы по запросу агента
(`start_environment`), останавливает простаивающие и удаляет окружение при
слиянии задачи. Агент порты и override-файлы не выбирает.

Окружение задачи — одноразовая копия основного. `scripts/task-env-clone.ps1`
копирует в тома проекта задачи секреты инстанса, media и базу `chatballs`
(логическая копия `pg_dump`/`pg_restore`, основная база продолжает работать).
Перед запуском воркера скрипт применяет миграции штатным `init` в копии и
выполняет `prepare_installation_copy --confirm-independent-copy`. Команда
выдаёт копии новый UUID, сбрасывает расписание и сообщения Backoffice и
выключает внешние проверки. При переносе или восстановлении той же установки
UUID сохраняется. `compose.task.yaml` держит
PostgreSQL, Redis и media задачи в томах её проекта, а не в каталоге checkout.
Существующие учётные записи основной базы работают, новые не создаются. Всё,
что задача изменила в своей копии, исчезает вместе с ней: ценные данные живут
только в основном окружении. Основное окружение должно быть запущено
(`postgres` проекта `chatballs`), иначе копия не создаётся.

### Локальный контур «Северный ветер»

Для просмотра восьми готовых историй откройте «Диалоги» сразу после установки
демо-данных. Переписка, вложения и результаты уже сохранены в Chatballs.
«Настройки → Демо-данные → Переустановить» восстанавливает исходные истории.
Указания ниже относятся к отдельной проверке локальных сервисов.

В согласованной проверочной копии подключите `compose.demo-local.yaml` поверх
обычных файлов Compose. Каталоги `chatballs-mcp-demo` и
`chatballs-external-agent-demo` должны находиться рядом с каталогом
`chatballs`. Задайте `CHATBALLS_NORTH_WIND_SITE_ORIGIN` равным
адресу шлюза этой копии, который открыт в браузере. Используются штатные
backend и воркер. MCP доступен через внутреннюю сеть Compose, а ключи
доступа выдаются при установке демо-набора.

Из подготовленных диалогов примерки, обмена, коммерческого предложения
и работы с заказами ссылка «Открыть диалог в чате» ведёт в штатный веб-чат
того же клиента. После согласия можно продолжить переписку. На карточке
агента «Северный ветер · Помощник по заказам»
доступен штатный проверочный чат с теми же локальными шаблонами. Для
исполнителя включается привязка только к активному поколению демо. Локальный
HTTPS-шлюз выдаёт сертификат внутри сети Compose, его доверенный корень
подключён только к участникам демо. Общий режим внешнего исполнения
организации при установке и переустановке не меняется.

При переустановке прежние ключи и ссылки сразу теряют доступ. Очистку
запросов старого поколения в локальном томе исполнителя завершает штатный
воркер после публикации нового набора.

В диалоге Марии о тёплом костюме откройте ссылку «Открыть витрину и проверить
размеры». В каталоге выберите размер, точку и бюджет, затем нажмите «Подобрать
костюм». Штатный виджет покажет приглашение. После согласия сценарий первого
ответа запрашивает живой каталог через MCP. Карточки ведут к соответствующим
товарам и сохраняют выбранный размер и точку. Подтверждение на витрине создаёт
заказ и резерв в выбранном магазине.

Из диалога Андрея откройте «Открыть витрину с бонусами Андрея». При исходном
балансе 1 500 бонусов витрина показывает штатное приглашение. После согласия
агент читает баланс и условия для модели через локальный HTTP-инструмент.
В корзине включите списание 750 бонусов и подтвердите заказ. При исходных
ценах итог составит 26 160 ₽, а остаток бонусов уменьшится до 750 после
подтверждения.

Для проверки актуальности расчёта до первого заказа Андрея администратор
может изменить условия через локальный mock-магазин. Выполните `POST` на
`/api/v1/organizations/{id}/company/demo/shop/{generation}/loyalty-case/`
с `Idempotency-Key` и полем `case`. Значения `balance-600`, `price-plus-2000`
и `excluded` меняют баланс, цену или доступность списания соответственно.
`standard` восстанавливает исходные условия до заказа. После заказа начать
заново можно переустановкой набора.

В «Настройки → Демо-данные» установите или переустановите набор. Для проверки
задержки отправьте `POST` на
`/api/v1/organizations/{id}/company/demo/shop/{generation}/delivery/`
от администратора проверочной организации. Передайте заголовок
`Idempotency-Key` и тело запроса
`{"customer":"pavel","order_number":2043,"status":"delayed","confirmed":true}`.
Повторите запрос с тем же ключом и проверьте, что в журнале создан один запуск.
В диалоге Павла действие «Доставка · Запросить уточнение» ожидает
подтверждения сотрудника перед отправкой в локальный сервис.
Переустановка возвращает заказ и диалог в исходное состояние.

Фото дефекта можно повторно отправить в штатный входящий канал через
`POST /api/v1/organizations/{id}/company/demo/shop/{generation}/support-photo/`
с телом `{"dialog":"team"}` и заголовком `Idempotency-Key`. Для передачи
обращения об обмене используйте `{"dialog":"exchange"}`.

Для обмена заказа № 2042 укажите в чате размер XL. В «Центре» этого размера
нет, в «Горках» есть остаток. Затем назовите магазин и подтвердите заявку.
В ветке повреждения загрузите фото в чат. Отдельные подготовленные диалоги
показывают выдачу № 2044, задержку № 2045, истёкший срок обмена № 2046 и
возврат оплаты по заказу № 2047.

Для КП откройте демо-диалог школы «Высота», укажите количество по размерам,
город и бюджет. После выбора модели чат запросит реквизиты и подтверждение.
Готовый документ можно открыть и скачать в диалоге или на витрине. Ссылка
на запись демо-CRM появляется во внутреннем комментарии.

Ниже описан ручной запуск, применявшийся до Skaro.

Обычная основная копия сохраняет прежние `./data` и Docker secret volumes.
`CHATBALLS_DEV_DATA_DIR` в `compose.dev.yaml` позволяет разместить PostgreSQL,
Redis и media вне checkout. В production используются прежние именованные тома.

Для worktree используйте `scripts/task-dev.ps1`. Он требует имя окружения,
свободный диапазон из шести портов и абсолютный каталог данных вне всех worktree:

```powershell
./scripts/task-dev.ps1 -Name t-008 -PortBase 18020 -DataDir C:/ChatballsRuntime/t-008
```

Это запуск существующей базы: без `postgres/PG_VERSION` скрипт остановится.
Он также проверяет наличие исходных secret volumes проекта `t-008`.
Имя Compose нельзя менять при переносе данных: оно определяет секреты инстанса.

Для новой реальной установки владелец явно выбирает `-InitializeDatabase`.
Запуск выполнит штатные миграции; владельца и организацию создают через обычный
мастер первого запуска. Скрипт не создаёт пользователей или демонстрационные
данные. Новая установка не является восстановлением старой базы.

Порты: `PortBase` PostgreSQL, `+1` Redis, `+2` backend-app, `+3`
backend-platform, `+4` frontend, `+5` web-chat. Frontend использует свой
`backend-app` внутри того же Compose-проекта. Скрипт проверяет настоящий
`/api/v1/health/ready/` через frontend proxy (БД и Redis).

## Перенос существующих данных

1. Запишите исходное имя Compose и mount paths через `docker inspect`.
2. Остановите все сервисы, которые пишут в PostgreSQL, Redis и media.
3. Сделайте резервную копию и проверьте её; копируйте полный `data`, включая
   PostgreSQL WAL и служебные файлы, в постоянный каталог. Исходник сохраняйте.
4. Сохраните прежнее имя Compose и все три исходных secret volumes. Не используйте
   `down -v`, не удаляйте тома и не генерируйте новые пароли для существующей базы.
5. Задайте `CHATBALLS_DEV_DATA_DIR` и пересоздайте соответствующие сервисы штатным
   Compose. Проверьте mount paths, readiness и существующие данные/вход.

Если исходная база исчезла вместе с worktree, требуется её резервная копия.
Восстановление только исходников из Git не возвращает БД и media. Не направляйте
frontend на другую задачу, чтобы скрыть отсутствие API; общий backend должен
быть явно согласованной зависимостью с устойчивыми исходниками и данными.

`scripts/start.ps1` и `start.sh` предназначены для основной копии, не для
одноразовых worktree. Слияние задачи не должно удалять каталог, используемый
Docker как source mount.
