# Устойчивое выполнение сервисных действий

T-170 реализует ручной прямой вызов и сценарий с одним сервисным action.
Это часть SPEC-0037/ADR-0038: составные блоки T-171, события/связи T-172,
ИИ T-173 и доменные действия T-174–T-176 не объявляются выполненными.
Приёмка двух baseline зафиксирована владельцем 22.10.2026 в R-28;
карточка задачи не используется как доказательство приёмки дизайна.

## Граница эффекта

`execution/launch.py` сериализует команду и атомарно сохраняет зашифрованный
snapshot, ScenarioRun, ScenarioStep, безопасный журнал и штатный outbox.
Уникальность `(organization, scenario_key, trigger_key)` не содержит ревизии.
Стабильный UUID effect_key создаётся до запроса. Preview не создаёт запуск:
`plans.py` подписывает только digest точных параметров, контекста, ревизии,
подключения, версии и инициатора на 15 минут. Повтор команды возвращает прежний
Run; изменение входов не заменяет его snapshot.

`checkpoints.py` берёт короткие блокировки Run → Step → Integration,
выдаёт lease 90 секунд, увеличивает attempt/fence и сохраняет watchdog.
`runner.py` проверяет текущие права, условия, файлы, точное подтверждение,
подключение и версию до нового эффекта. OAuth refresh и внешний I/O выполняются
вне транзакции. Persisted send marker предшествует вызову обработчика.
Результат, переход состояния и следующее задание фиксируются атомарно с fence
и сроком lease; устаревшая попытка не перезаписывает checkpoint.

Восстановление применяет объявленную стратегию: тот же idempotency key,
reconcile, безопасное чтение или unknown без повторной записи. Истечение lease
не доказывает отсутствие внешнего эффекта. Exactly-once для произвольного API
не обещается. Потеря ответа записывающего запроса не становится обычной ошибкой,
позволяющей слепой повтор. Отмена/отзыв прав прекращают новые эффекты;
установление исхода уже посланного запроса сохраняется. Компенсация отдельная.

## Ограничения и штатный worker

`execution/worker.py` использует 2 ограниченных in-process слота внутри каждого
существующего worker-events. Занятый слот не блокирует dispatcher сообщений/ИИ;
claim с watchdog фиксируется до передачи в поток и ACK outbox.
По подключению действует DB lane и cooldown. Транспортный timeout ограничен
30 секундами, ответ/файл — Limits адаптера. Доверенный программный обработчик
обязан соблюдать deadline: Python-поток не является изоляцией произвольного кода.
Автоповторы ограничены шестью попытками; backoff с jitter до 300 секунд учитывает
более долгий Retry-After, включая HTTP-date. Ожидание — future outbox, не sleep.
Новый брокер или обязательный worker-сервис не вводится.

## Доступ, журнал и очистка

Run API использует текущий membership и tenant/RLS. Общий журнал — OWNER/ADMIN;
конкретный запуск в диалоге — текущая conversations.view. Управление проверяется
отдельно. Выполнение прямой операции сотрудником требует конкретного ActionGrant;
миграции никому его не выдают. Управление делегированием ещё не имеет продуктового
экрана в этой задаче. Просмотр не расширяет разрешения. Conditions/contact identity
и типизированные значения проверяются заново до запроса.

Payload хранится только зашифрованно в операционном состоянии, не в outbox/журнале.
API значений применяет схемную и credential redaction. Safe journal — коды,
пути/attempt, время, безопасные названия и состояния. Realtime шлёт invalidation
без идентификаторов через штатные группы; чтение API повторно авторизуется.

Cleanup в существующем poller ограничен 50 завершёнными запусками за порцию.
По умолчанию 7 дней очищают операционное состояние, 30 — safe history/steps,
инициатора, контекст и структуру. Unknown останавливает автоматику и имеет время
завершения; явная сверка снова делает запуск активным и защищает данные.
StepOperationalFile удерживает файлы всех потребителей. Outbox физически удаляет
orphan без independent_owner, сохраняя строку и квоту при ошибке для повтора.
Ручная команда не имеет срока replay, поэтому её минимальный dedup tombstone
не истекает; payload/actor/context в нём не остаются. Окна будущих триггеров не
придумываются. Сокращение 7/30 требует подтверждения, получает 24 часа, может
быть отменено возвратом срока и не задерживает обычную очистку. Аудит отдельный.

## Открытые ограничения проверки

В копии окружения отсутствует подключённый внешний сервис. Владелец выбрал
продолжение без доступа: реальный эффект/справочники и UI заполненных запусков
не выдаются за проверенные. Тестовые descriptors используются только в unit/
PostgreSQL тестах, не как сервер или подмена штатного приложения.

Каталог T-169 предлагает conversation.topic, метки контакта и условие EntityLink.
В текущих Conversation/Contact нет источника первых двух; EntityLink — T-172.
По явному решению владельца от 30.10.2026 эти источники отложены, внешние связи
остаются T-172. Зависимые bindings/guards блокируются, включая отрицательное
«темы нет», режим any и object.get ссылки. Каталог помечает такие действия
недоступными с причиной; preview/launch, справочники и повторные проверки перед
эффектом используют тот же gate `execution/source_support.py`. Отсутствие
реализованного источника не считается доказательством отсутствия бизнес-данных.
Остальные одношаговые запуски не блокируются; данные не выдумываются.
Чтение schema-only native action не объявляется его исполнением.
