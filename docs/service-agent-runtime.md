# Действия в существующем runtime ИИ

T-173 уточняет SPEC-0037 R-14–R-17, R-24–R-30 и ADR-0038. Оба baseline лично
приняты владельцем 22.10.2026; запись приёмки находится в документах Skaro.
Ни этот документ, ни принятие архитектурного пакета не подтверждают публикацию.

## Полномочия и исполнение

`AgentActionGrant` хранит ровно одну пару агент–операция подключения либо
агент–сценарий, режим off/self/ask и монотонную ревизию. Миграция создаёт только
таблицу, RLS и проверки tenant-связей. Редактор сценария и карточка агента меняют
одну запись с проверкой ревизии. Старый access.aiMode, навыки и HTTP/MCP grants
не становятся разрешениями новых действий.

`execution/ai_bridge.py` добавляет инструменты в прежний `plan_chat`/tool-loop.
Схема содержит только объявленные аргументы и отдельный инструмент статуса.
Организация, агент, диалог, grant, версия конфигурации и управления связаны
сервером. Модель не выбирает tenant, секрет, произвольное подключение или связь.
`ai_launch.py` использует прежние snapshots, Run/Step и outbox; runner остаётся
единственным исполнителем. Режим self разрешает и запись/удаление без общего
подтверждения. Все прежние budgets, lease/fencing и unknown/reconcile сохраняются.

Перед эффектом проверяются текущие grant/ревизия, агент/конфигурация, режим
организации, подключение, сценарий и контекст. PostgreSQL монотонно меняет
`Conversation.ai_control_version` при перехвате/назначении/смене канала/закрытии
и архивировании. Возврат прежнего значения состояния не оживляет старый Run.
Вложенный сценарий наследует привязку и проверяет всех предков; неактивное или
неделегированное вложение не повышает полномочий.

## Точное подтверждение

Режим ask создаёт ожидание на 30 минут. Digest связывает Run, путь, effect key,
операцию/версию/подключение, параметры, контекст и привязку ИИ со сроком.
Решение принимает текущий администратор либо уполномоченный ответственный;
видимость карточки отдельно от права решения. Перед эффектом повторно
проверяется действительность сотрудника и подтверждения. Текст модели и
внешнего события не является решением.

Редактирование арендует конкретный запрос одним сотрудником на пять минут,
ограниченных общим сроком. Изменяются только разрешённые входы текущего Step;
определение сценария не переписывается. Сохранение подтверждает новый digest,
старые значения не подходят. Конкурирующие решения сериализуются теми же
блокировками. Outbox срока ожидания останавливает новые несостоявшиеся эффекты.

## Privacy и долгий результат

Описания/схемы, аргументы и результаты проходят карту псевдонимов текущего хода.
Сервер раскрывает известные значения только перед исполнением. Карта живёт в
памяти. Операционный журнал содержит коды и идентификаторы, без сырых промптов,
ответов старых инструментов и секретов. Значения Run/Step хранятся в прежнем
зашифрованном контуре с действующим retention 7/30 и владением файлами.

Запуск возвращает Run ID и фактическое queued/approval/pending/completed и т.д.
Воркер не ждёт завершения внутри tool-loop. Инструмент статуса повторно
проверяет привязку; следующий обычный ход получает ограниченный список
доступных запусков с текущими аргументами, включая исправления сотрудника.
Результаты остаются недоверенными данными. Получение статуса после завершения,
фиксация ответа и фактическая отправка повторно проверяют текущие права,
агента, режим и управление. Второго фонового цикла модели или замены провайдера
нет. Внешний исход после отзыва можно установить для журнала, без новой
автономной отправки.

## Проверочный чат и UI

По умолчанию preview проверяет параметры без Run и outbox. Явный execute
создаёт настоящий Run с текущим сотрудником проверки, теми же grant и ask.
Предупреждение не обещает отсутствия записи в этом режиме. Экран использует
принятые «Агент · действия» и «Запуск из диалога»: три режима, параметры
подтверждения, карточку в ленте и редактор запроса; все тексты ru/en.
Справка: [ru](agent-actions.ru.md), [en](agent-actions.en.md).

## Архитектурные границы и доказательства

Контекст и контейнеры прежние: Django backend, PostgreSQL/RLS, Redis,
worker/worker-events, inbox/outbox и рабочий интерфейс. Новых служб нет.
Компоненты: существующие AI/privacy/conversations и planned policy/runner/state.
Код: execution/ai_bridge, ai_launch, ai_policy, ai_approval, ai_context,
scenario_state/agent_grants, агенты/actions и integrations/runs.
Ordered dynamic-ai включает настройку, маскирование, запуск, решение, эффект,
статус и проверку доставки. Context/container/component/code/deployment/dynamic
применимы и покрываются общим пакетом C4 Skaro; исключённых уровней нет.
Planned сохраняется до проверенной публикации, без реализации всех родительских
компонентов одной задачей.

Автоматические контрактные проверки используют независимый адаптер только
в тестовой базе; это не проверка настоящего внешнего сервиса. Отсутствие
установленного подключения/доступа нельзя заменять временным backend или seed.
