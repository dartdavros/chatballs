# Редакционный порядок центра помощи Chatballs

`chatballs.json` задаёт порядок опубликованных статей внутри каждого раздела и
направленные связи между статьями. Карта охватывает 75 русскоязычных статей и
180 переходов. Она не меняет тексты, категории и статусы публикации.

`articles/trebovaniya-k-serveru.yml` содержит русскую статью «Требования к
серверу»: минимальные ориентиры по диалогам в день, отдельный расчёт сети
для звонков и диска для вложений. Оценки производительности обозначены как
предварительные. 8 октября 2026 года статья импортирована и опубликована
по запросу владельца в разделе «Установка и сервер» перед первым запуском:
статья 83, ревизия 380,
<https://chatballs.com.edevs.tech/articles/trebovaniya-k-serveru>.
Порядок и связи остальных разделов при публикации не изменялись.

`articles/klassy-vidzheta.yml` содержит статью «Классы виджета» в штатном
формате импорта статей портала. Её текст сверяется с
`apps/web-chat/src/widgetClasses.ts` тестом `widgetClassesDocumentation.test.ts`:

```sh
npx vitest run docs/portal-curation/widgetClassesDocumentation.test.ts
```

`articles/instrumenty-agenta.yml` содержит статью «Инструменты агента» на ru и
en: подключение MCP и HTTP, привязка параметров, проверка владельца заказа.
Обе версии используют slug `instrumenty-agenta`. Ссылки из предупреждений
на страницах внешних серверов используют `helpArticleUrl("instrumenty-agenta")`.
Статья проверяется штатным парсером импорта и Markdown-рендерером:

```sh
npx vitest run docs/portal-curation/agentToolsDocumentation.test.ts
```

Обе версии импортируйте в существующий раздел «ИИ-агенты» (`agents`):
категории портала общие для языков, язык задаётся у самой статьи.
Карта `chatballs.json` задаёт порядок только русских статей. Для обеих версий
нужно опубликовать импортированную ревизию. Публикация действующего центра
помощи требует согласования владельца, как и для статьи «Классы виджета».

5 октября 2026 года обе редакции импортированы и опубликованы в действующем
центре помощи с разрешения владельца. Статьи ru/en имеют номера 81/82,
опубликованные редакции — 378/379. Русская статья открывается по адресу
<https://chatballs.com.edevs.tech/articles/instrumenty-agenta>, английская
опубликованная редакция доступна через штатный API статьи с `locale=en`.
Переходы из предупреждений MCP и HTTP проверены в браузере.

5 ноября 2026 года по запросу владельца в обе версии добавлен раздел о
публичном стенде `https://mcp-test.chatballs.ru/mcp`: подключение без
авторизации, четыре инструмента с параметрами, демо-товары и заказы,
примеры сообщений, пустые результаты и ошибки. Опубликованы ревизии
401/402 статей 81/82. Прежний текст, категории и порядок сохранены.
Проверка импорта и Markdown-рендерера прошла; русская статья проверена
в браузере. Сервис также проверен настоящим MCP-клиентом установленного CB.

При реализации раздела «Оформление» ссылка «Классы виджета» должна получить
адрес `helpArticleUrl("klassy-vidzheta")` из `shared/help`. В текущей версии
`WebIntegrationPage` этот раздел отключён; подключение ссылки и проверка
перехода зависят от реализации раздела в T-023.

Добавление YAML в репозиторий само по себе не публикует статью. Перед
применением обновлённой карты нужно импортировать YAML через библиотеку
статей центра помощи в существующий раздел «Точки входа» и опубликовать
ревизию. Изменения действующего портала выполняются только после
согласования с владельцем. До публикации новой статьи проверка карты
завершится ошибкой состава статей.

Команда `apply_portal_curation` сначала проверяет, что карта полностью совпадает
с опубликованными статьями выбранного портала: состав, разделы, язык и ссылки.
Без `--apply` она только показывает число записей, которые были бы изменены.

После штатной выкладки версии с миграцией `0012_article_curation`:

```sh
cat chatballs.json | ssh ubuntu@SERVER \
  'cd /home/ubuntu && docker compose exec -T backend-admin \
  python /app/apps/backend/manage.py apply_portal_curation \
  --host chatballs.com.edevs.tech --file -'
```

После сверки результата тот же запуск с `--apply` сохраняет порядок и связи.
Повторный запуск идемпотентен: при уже применённой карте число изменений равно
нулю. Файл передаётся через stdin и не сохраняется на сервере, поскольку
production-образ не содержит этот каталог документации.
