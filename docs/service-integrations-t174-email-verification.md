# T-174 — почтовое продолжение

Промежуточная реализация; полная приёмка задачи ещё не выполнена.

Четыре `messages.email_*` действия вызывают прежние send/retry services;
защищённые чтения вынесены в `conversations/email_queries.py` и используются
тем же HTTP API. Сохраняются текущая видимость, назначение, сохранённый адрес,
WEB-источник, действующий почтовый ящик и неизменный маршрут повторов.
Схемы содержат отдельные параметры, typed operation/attempt/state и ru/en.

`send_email_reply` только создаёт прежние EmailSendOperation/Attempt/outbox.
Исходные ключи берутся из step.effect_key; новая попытка не появляется при
восстановлении завершённого шага. Результат по-прежнему deliveryConfirmed=false.
UNKNOWN не даёт неявного повтора: требуется acknowledgeUnknown.

Нормальный файловый opener ограничен входными ссылками, tenant и размером;
он доступен и локальным действиям. Почтовый сервис сохраняет исходную атомарную
границу очереди, доменного факта и receipt/checkpoint; SMTP здесь не вызывается.
Код сборки NativeContext вынесен из native_io в native_context без второго
набора правил. Открытие/хранение файлов использует прежнее хранилище.

Штатный `start_environment` обновлён, `manage.py check` пройден.
Текущий адресный прогон выполняется, результаты и browser-проверка будут
зафиксированы после завершения:

```sh
docker compose exec -T backend-admin python -m pytest chatballs/integrations/action_catalog/test_native_email.py chatballs/integrations/action_catalog/test_native_io.py chatballs/integrations/action_catalog/test_catalog_coverage.py chatballs/conversations/test_email_send_api.py chatballs/integrations/action_catalog/test_native_comments.py::NativeCommentTests::test_runner_appends_internal_once_and_keeps_result_encrypted chatballs/i18n/tests.py::CatalogTests --reuse-db -q --tb=short
```

Реальный SMTP не проверен: в штатном демо-контуре почтовый poller получает
ошибку DNS. Настройки/секреты/права не менялись, временный SMTP не создавался.

Первый адресный прогон: 19 passed, 4 failed, 349.55 с. Все исходные API,
coverage/i18n, локальный комментарий и I/O crash recovery прошли. Четыре
новых проверки ошибочно наследовали TestCase с внешней транзакцией. Runner
закономерно отказал ещё до исполнения. Фикстура переведена на TransactionTestCase;
защита runner не ослаблялась. Повторяются только эти четыре проверки.
