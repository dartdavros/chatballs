# Редактор сценариев

Настройки → «Сценарии» доступны владельцу и администратору организации.
Создайте сценарий или откройте карточку подключённого сервиса и нажмите
«Настроить» у готового сценария. Полученная копия принадлежит вашей организации:
её можно менять, копировать и удалять. Обновление пакета сервиса её не заменяет.

## Запуск → Условия → Шаги

В «Запуске» выберите сотрудника, ИИ, событие Chatballs или сервиса, расписание,
внешний API либо другой сценарий. Несколько способов могут работать совместно.
Настройте доступ сотрудников и групп, область действия, режим ИИ и подтверждение.
Запуск без сотрудника требует явного разрешения. Сохранение этих настроек само
по себе не выдаёт права сотруднику или агенту и не выполняет действий.

Расписание использует часовой пояс организации. Можно выбрать каждый день,
будни, дни недели или число месяца, время и поведение при пропуске. Переход часов
имеет фиксированное правило: первое вхождение повторившегося времени, пропуск
несуществующего времени. Это правило хранится в определении.

Условия проверяют выбранные поля. Для действия выберите подключение, операцию
и значения её полей. Список операций, справочники и типы предоставляет
установленный адаптер. Для обычного сценария не нужны код, JSON или граф.

Значение можно задать явно, спросить при запуске у сотрудника/ИИ, получить из
доступного контекста, события, предыдущего шага или текущего элемента перебора.
У результата выбираются шаг и конкретное поле. Доступны зарегистрированные
преобразования и ссылки на файлы организации. Вложенные объекты и списки
заполняются теми же формами. Произвольный программный код не исполняется.

Помимо действий есть «Если», «Для каждого», «Одновременно», «Запустить другой
сценарий», «Подождать» и «При ошибке». Ветви, перебор и обработчик ошибок имеют
свои списки шагов. В обработчике доступны причина ошибки, шаг, сервис и запуск.
Входы вложенного сценария заполняет вызывающий сценарий; повышение прав через
вложенный вызов не допускается.

## Сохранение

Незавершённые настройки можно сохранить выключенными. Перед включением
проверяются обязательные значения, типы и ссылки. Пустая обязательная константа
или удалённый источник блокируют включение. Перед реальным действием фактические
значения также должны пройти проверку.

Если другой администратор сохранил новую версию, редактор не перезапишет её.
Загрузите актуальную версию и повторите свои изменения. При выходе с несохранёнными
изменениями можно сохранить их, отказаться от них или остаться в редакторе.

После сохранения способа внешнего запуска доступны адрес и пример запроса.
Новый ключ показывается один раз: скопируйте его до закрытия панели. Позднее
показывается маска. Явный перевыпуск заменяет ключ, старое значение удаляется.

## Обмен связанными записями

В карточке сервиса откройте «Обмен данными». Выберите пары записей и направление,
затем поля каждой пары. Для перечислений и справочников настройте соответствия
значений отдельно в каждом направлении. «Не менять» сохраняет значение получателя.
Задайте правило конфликта и удаления. Обмен не создаёт связи по совпадению телефона
или почты: запись должна быть связана явно.

## Примеры настройки

Для проверки структуры без внешнего сервиса создайте сценарий с запуском
сотрудником. В условиях выберите «Контакт диалога» → «Контакт есть», в шагах —
«Подождать» → указанное время, 1 час. Сохраните и откройте снова: условие и
длительность должны сохраниться. Это проверка определения, не исполнения.

Для обработки списка выберите операцию установленного сервиса, которая
возвращает список. Затем добавьте «Для каждого», выберите список из результата
первого шага и добавьте действие во внутренний список. Его поля могут брать
значения из «Текущего элемента». Добавьте «При ошибке», чтобы отдельно заполнить
основные шаги и обработчик; в обработчике доступен источник «Ошибка».
После шага условие «Результат шага» → «Как завершился шаг» позволяет выбрать
успех или ошибку. Значения соседней ветки и будущих шагов не предлагаются.

## Что входит в эту поставку

Редактор сохраняет и проверяет определения, ключи внешнего запуска и настройки
обмена. Исполнитель, автоматические подписки, endpoint запуска, ожидания,
предоставление разрешений ИИ и фактический обмен подключаются отдельными задачами.
Сохранение или включение определения в этой поставке не является проверкой
выполнения сценария во внешнем сервисе.
