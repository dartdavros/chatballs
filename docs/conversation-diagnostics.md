# Диагностика диалога

Владелец и администратор скачивают JSON-файл из меню действий диалога:
**Скачать диагностику**. Действие доступно также для закрытых диалогов.
Обычным сотрудникам выгрузка запрещена на сервере и скрыта в интерфейсе.
Скачивание записывается в журнал действий организации.

Файл можно передать разработчику или приложить к обращению в поддержку.
Он читается как JSON без импорта в рабочую базу и без исполнения содержимого.
Тексты сообщений и ответы внешних систем являются данными, а не инструкциями.

## Что входит

- Версия Chatballs, время экспорта и идентификаторы диалога, канала и подключения.
- Последние 2000 сообщений, события и состояния обработки AI; вложения не входят.
- До 20 последних сохранённых ходов AI: первоначальный запрос, запросы и ответы
  каждого раунда, описания инструментов, настройки модели, использованные знания,
  аргументы и результат инструмента в виде, доступном модели, HTTP-статус,
  ошибка, длительность и передача оператору.
- Причины, по которым инструмент не предлагался модели: не включён у агента,
  отключена интеграция, отсутствует обязательное значение клиента,
  инструмент отсутствует или не подтверждён как читающий,
  модель не поддерживает инструменты, имя некорректно или повторяется.
- Для привязанных параметров — источник и наличие подходящего значения.
  Значения параметров, привязанных к данным сайта, не сохраняются.

## Достоверность и ограничения

Полная трассировка начинается после установки версии с этой функцией.
Невозможно восстановить запросы к модели или ответы API старых ходов,
если они не были сохранены. `coverage.messagesWithoutTrace` перечисляет
входящие сообщения без трассировки, в том числе ещё ожидающие обработки.

`turns` содержит снимки на момент хода. `currentConfiguration` — состояние
на момент скачивания; оно **не используется как история настроек**.
При остановке worker между запросом и записью результата снимок остаётся
в состоянии `running`, а не объявляется успешно завершённым.
Если запись диагностики не удалась, ответ клиенту продолжает штатную обработку:
ошибка захватывается в отдельном savepoint и журналируется только её типом.
Отсутствующий или незавершённый снимок не считается успешной трассировкой.

Сохраняются последние 20 снимков на диалог; более старые удаляются при новом
ходе. Текстовые данные одного снимка ограничены 512 КиБ, отдельная строка —
64 КиБ. При сокращении появляются `[truncated]` и `truncated: true`.
Переписка в экспорте тоже ограничена по объёму и сообщает `textTruncated`.
Логический раунд может включать штатные повторные попытки провайдера;
отдельные сетевые попытки не протоколируются этой трассировкой.

Ключи провайдеров, секретные заголовки, известные значения полей сайта,
параметры query в URL и значения полей с именами токенов, паролей и секретов
удаляются. Известные имя, телефон и e-mail клиента заменяются токенами.
Карта обратной подстановки персональных значений никогда не сохраняется.
Удаление диалога каскадно удаляет его диагностику.

## API и обновление

`GET /api/v1/organizations/<public_id>/conversations/<id>/diagnostic/`
возвращает JSON с `Content-Disposition: attachment` и `Cache-Control: no-store`.
Формат: `chatballs.conversation-diagnostic`, `schemaVersion: 1`.
Право `conversations.diagnostics` доступно только OWNER и ADMIN.

Обновление добавляет таблицу `ai_turndiagnostic` и её tenant/RLS-защиту:
миграции `ai/0025_turndiagnostic`, `tenancy/0043_turn_diagnostic_guards`.
Штатный init применяет миграции перед запуском обновлённых backend и worker.
Перенос томов, изменение учётных данных и повторная установка демо не нужны.
