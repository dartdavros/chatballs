## Цель

Реализовать подключение реально установленного адаптера через третью группу и выдачу его схем/готовых сценариев. Сохранить существующие подключения и разрешения; общий контракт покрывает будущие сервисы без ветвлений ядра.

## Критерии приёмки

- [x] Обязательный gate: реализация начинается только после явно зафиксированной личной приёмки владельцем ОБОИХ результатов baseline; принятие карточки плана/задачи не является приёмкой макета. Основание: SPEC-0037 R-28.
- [x] Integration получает SERVICE с общим ADAPTER и отдельными adapter_key/version/settings/защищёнными credentials. Подключение tenant-изолировано, не требует Channel/AIAgent; несколько экземпляров и жизненный цикл/check/is_active работают по baseline.
- [x] Реестр описывает версии, схемы настроек/доступа/операций/результатов, события, справочники и пресеты; объявленные execute/resume/reconcile/cancel/ingress/poll handlers валидируются. Поддерживаются вложенные типы, nullable, списки, даты/справочники/файлы и длительные операции, без общего CRM-формата.
- [x] Работают настраиваемые HTTP/API и MCP-адаптеры, версионированные расширения авторизации/транспорта/преобразований/контролов и доверенные программные адаптеры. Методы/тело/данные не урезаны до чтения; ограничения внешнего сервиса объявлены явно.
- [x] Старые HTTP/MCP доступны через совместимый мост без копирования/потери секретов, переподключения и автоматического расширения read-only-разрешений; записывающее действие не требует ложной отметки «только чтение». AI-провайдеры/мессенджеры сохраняют назначение.
- [x] Доступны предусмотренные адаптером ключи/Basic/Bearer/OAuth/подписи/сертификаты/специфические механизмы. Одноразовый OAuth state привязан к пользователю/tenant/подключению, refresh сериализован, отзыв/истечение показаны. Проверка не выполняет скрытых бизнес-изменений.
- [x] Секреты не попадают в UI/ИИ/логи/outbox, транспорт соблюдает действующую DNS/redirect/SSRF и сетевую политику; большие/бинарные данные используют штатное файловое хранилище.
- [x] UI каталога/подключения/карточки/пресетов реализован по лично принятому baseline; каталог показывает только установленные адаптеры. Пресет содержит назначение, обязательные подключения/права, параметры и шаги; незаполненные настройки не вызывают скрытого включения.
- [x] Затронутые проверки покрывают schema/registry, OAuth/tenant, секреты/сеть/файлы и обратную совместимость; UI проверен браузером. Контракт адаптера/расширений и справка подключения обновлены в этой задаче.

## Заметки

Причина выделения: законченный пользовательский результат подключения/проверки сервиса и каталога. Контракты, HTTP/MCP/доступ и их UI держатся вместе; создание сценариев и распределённый по времени исполнитель слишком велики для этого же bounded-сеанса. Функция SPEC-0037 не объявляется полностью готовой после этой задачи. Пути: integrations/adapters/, service_connections/, scenario_state/connections.py, существующие models.py/outbound.py; UI features/integrations/services/. C4: registry/connections, planned code и dynamic-setup. Основа: SPEC-0037, ADR-0038, docs/service-integrations-c4.md и актуальный get_c4_context. Один backend/штатные PostgreSQL, worker/worker-events, inbox/outbox, tenant/RLS; без новых обязательных служб. Соблюдать AGENTS.md, DRY/KISS/SRP, NO GOD FILES, отдельные model/API/subviews, i18n ru/en. Проверки: сборка для изменений кода и только непосредственно затронутые тесты (backend --reuse-db), UI — браузером в штатном контуре. Без полного прогона, seed, временных API/fake backend и изменения доступов ради проверки. Для новых внешних доступов использовать реальный штатный контур; отсутствие доступа фиксировать как blocker, не выдавать непроверенное за пройденное. Перед submit_result прочитать get_c4_context, сверить реальные изменения со спецификацией/C4; необходимые изменения документации/архитектуры предложить единым propose_c4 и получить принятие, затем review_c4 с точным changeHash, затронутыми ID и доказательствами из кода. После изменения кода/документов повторить review. Planned не объявлять current до проверенной публикации.

## Итог

Реализованы сервисные подключения, реестр/расширения, HTTP/MCP и совместимый мост, OAuth и установленный Битрикс24 с определением пресета. Каталог, подключение и карточка проверены по принятому baseline в штатном окружении; документация и принятый C4 rev.4 соответствуют коду. Редактор, исполнитель сценариев и весь этап не объявляются завершёнными; ограничения реального user.get и DNS явно зафиксированы.
