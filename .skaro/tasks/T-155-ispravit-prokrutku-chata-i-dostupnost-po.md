## Цель

Устранить перекрытие последнего сообщения и лишний отступ над редактором. Исправить причину, по которой существующие настроенные почтовые подключения не доступны для письма из диалога.

## Критерии приёмки

- [x] При открытии и переключении диалогов лента доходит до последнего сообщения: сообщение целиком видно над редактором без ручной прокрутки.
- [x] Над полем ввода устранён отмеченный владельцем лишний пустой отступ; переключение «Ответ клиенту / Письмо / Комментарий» и изменение высоты редактора не перекрывают последнее сообщение.
- [x] Чтение старых сообщений и подгрузка истории сохраняют позицию; поступление сообщения не сбрасывает пользователя вниз, если он читает историю.
- [x] Причина исключения двух существующих почтовых подключений установлена по штатному API и состоянию подключений; исправлено ошибочное исключение пригодных ящиков или дефект штатной проверки. Статус успеха не подставляется искусственно, фильтры организации и безопасности не ослабляются.
- [x] В редакторе письма доступны оба ящика, если оба действительно пригодны; выбранный ящик сохраняется до отправки, письмо отправляется через него штатным механизмом. Реально непригодный ящик не предлагается как рабочий, причина недоступности понятна.
- [x] Проверка проведена в браузере на реальном backend для открытия чата, переключения режимов и выбора почты; необходимые изменения кода прошли сборку и только адресные тесты. Нет заглушек, seed, изменений учётных данных и production; проверены i18n и размер/ответственности изменённых файлов.

## Заметки

Замечания владельца №1–2, скрины чата и письма из проектного чата 15.10.2026. Граница: один рабочий сценарий оператора — видеть последнее сообщение и отвечать, включая письмо. Отдельная задача от управленческих экранов позволяет проверить и принять рабочий чат независимо; разбиения на backend/frontend нет. Источники: useHistoryScroll.ts, historyScrollState.ts, layout ленты/редактора, email_options.py, интеграционные проверки и useEmailComposerDraft.ts. Не считать отсутствие статуса OK доказанной причиной: mailbox_available проверяет status != ERROR и ряд других условий. Без ручной смены статуса, перепривязки ящиков, изменения секретов или отправки тестовых писем посторонним адресатам; если штатный контур недоступен — сообщить точный blocker. Дизайн сохраняется, исключение — явно потребованное устранение лишнего отступа и перекрытия. Не добавлять новую функцию или новые экраны.

## Итог

Исправлены открытие и переключение чатов, перекрытие последней записи, лишний отступ и сохранение позиции при росте редактора, чтении и догрузке. По прямому решению владельца почтовое продолжение WEB больше не требует привязки ящика к агенту; исправлены доступность и poller, сохранены изоляция организации, проверки подключений, выбранный ящик и штатный outbox. Код закоммичен и проверен; внешняя почтовая приёмка отдельно не подтверждена, дополнительных данных владельца для реализации исправлений не требуется.
