## Цель

Реализовать помощь в редакторе ответа. Реализовать утверждённые состояния интерфейса поверх штатного API после готовности бэкенда и утверждения дизайна.

## Критерии приёмки

- [x] Запрос, ожидание, ошибка, альтернативы и отклонение соответствуют утверждённым состояниям.
- [x] Редактирование и ручная отправка сохраняют связь с предложением; текст не отправляется генерацией.
- [x] Браузерная проверка подтверждает полный сценарий на реальном бэкенде.

## Заметки

Основание границ задачи: Интерфейс помощи остаётся отдельным: ему нужен утверждённый макет всех состояний, тогда как серверный цикл можно проверить и завершить раньше.

Покрытие исходных требований:
T-087 — SPEC-0024: R-6–R-9

Все исходные критерии приёмки перенесены дословно. При реализации сохранить применимые требования действующих спецификаций 0001, 0004, 0008, 0009, 0017 и 0018. Реализация, необходимые тесты, документация и проверка результата входят в эту же задачу.

## Итог

Редактор ответа получил помощь с черновиком по утверждённому макету design/baseline/platform-expansion (кадры A1–A11, K1): кнопка «Черновик AI», панель ожидания/готового текста/альтернатив/ошибки, отклонение, метка у вставленного текста и строка вкладок. Клиенту текст уходит только ручной отправкой вместе со ссылкой на выбранное предложение; в детальную карточку диалога добавлено поле replyAssistanceEnabled для кадра A10. По решениям владельца кнопки «Остановить» нет (сервер не отменяет генерацию), строка вкладок добавлена с одной вкладкой «Ответ клиенту».
