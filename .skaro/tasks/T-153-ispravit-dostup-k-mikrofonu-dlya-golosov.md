## Цель

Устранить блокировку записи голосовых при встраивании виджета на сайт с другим origin. Лоадер должен делегировать iframe доступ к микрофону, сохраняя запрос согласия пользователя и действующие ограничения браузера.

## Критерии приёмки

- [x] Публичный лоадер /chat-widget.js задаёт iframe разрешение microphone для origin его src до вставки в DOM; разрешение не распространяется на произвольные origins и не добавляет доступ к камере.
- [x] В штатном контуре на HTTPS-сайте с origin, отличным от установки, и без запрещающей политики родителя нажатие записи позволяет запросить разрешение браузера; после согласия голосовое записывается, отправляется через реальный backend и воспроизводится в диалоге.
- [x] Отказ пользователя или запрет microphone политикой родителя не обходятся: виджет остаётся в состоянии idle, показывает существующую ошибку и не отправляет голосовое; после разрешения доступа браузером запись можно повторить.
- [x] Существующее поведение сохраняется: при запрещённых в подключении голосовых кнопка скрыта; микрофон не запрашивается при загрузке или открытии виджета, а только по нажатию записи; макет и продуктовые тексты не изменены.
- [x] Добавлена целевая регрессионная проверка разрешения microphone у создаваемого iframe публичного лоадера; пройдены только относящиеся к изменению проверки и необходимая сборка затронутого приложения, выполнена браузерная проверка на реальном контуре; изменённые файлы соответствуют NO GOD FILES.

## Заметки

Диагностика 08.10.2026: apps/backend/chatballs/webchat/loader_assets/runtime.js:29–33 создаёт iframe, задаёт src/title/style, но вообще не задаёт allow. Панель загружается с origin установки, вычисленного по script.src; поэтому стандартный сценарий на внешнем сайте является cross-origin. По Media Capture and Streams §14 microphone имеет default allowlist self: без делегирования iframe браузер блокирует getUserMedia({audio:true}) (NotAllowedError), часто без запроса пользователю. Исправление: минимальная делегация microphone для src, например allow="microphone 'src'", до монтирования iframe. apps/web-chat/src/useVoiceRecorder.ts:49 вызывает getUserMedia, а catch:85–86 сводит все ошибки начала записи к chat.no_mic_access — эта надпись не подтверждает отсутствие устройства и скрывает причину блокировки. Менять UX/словарь или расширять обработку ошибок в рамках задачи не требуется. /chat/ в deploy/nginx/frontend.production.conf и local.conf не содержит запрещающего Permissions-Policy; разрешение на /calls/ относится к отдельной странице и не исправляет iframe. Политику стороннего родителя обойти нельзя. Основание: SPEC-0001 R-4, R-8, R-12, R-15. Источник: https://www.w3.org/TR/mediacapture-streams/#permissions-policy-integration ; https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Permissions_Policy . Факт дефекта подтверждён чтением кода, браузерное воспроизведение конкретного обращения владельца не выполнено: адрес страницы не предоставлен, полный основной локальный контур не запущен (docker ps показывает frontend/postgres/redis; полноценные сервисы T-062 принадлежат другой задаче). Чужой контур не изменять и не использовать для исправления этой задачи. Не создавать временный сервер, fake backend, fixtures или seed ради браузерной проверки. Проверять через существующий сайт/портал с реальным backend; при недоступности сообщить blocker владельцу. Задача самостоятельная, без этапа и без зависимостей.

## Итог

Лоадер делегирует iframe только microphone для origin src до монтирования; добавлен целевой регрессионный тест. Штатное окружение T-153 восстановлено, gateway доступен на выделенном Skaro порту 20055, запись с реального микрофона, отправка через backend, воспроизведение, отказы и скрытие кнопки проверены локально. Владелец попросил отметить результат готовым и сообщил, что оставшуюся проверку выполнит сам; HTTPS cross-origin сценарий агентом не подтверждён.
