## Цель

Завершить единый интерпретатор для последовательностей, условий, перебора, параллельных ветвей, вложенных сценариев и ожиданий. Любой составной сценарий использует тот же путь эффекта, прогресс и права.

## Критерии приёмки

- [x] Обязательный gate: реализация начинается только после явно зафиксированной личной приёмки владельцем ОБОИХ результатов baseline; принятие карточки плана/задачи не является приёмкой макета. Основание: SPEC-0037 R-28.
- [x] Последовательности, if/foreach/parallel/call/wait/try и обработка ошибок исполняются по сохранённому снимку. Входы/выходы/преобразования и зависимости проверяются до следующего эффекта; path различает блок/итерацию/ветвь, прогресс сохраняется отдельно.
- [x] Независимые ветви, join и вложенные Run переживают падение без повтора успешных эффектов/потери частичного результата; полномочия вложенного вызова не шире родительских. Изменение определения не переинтерпретирует активный Run.
- [x] Ожидания времени, подтверждения, внешнего долгого результата и события сохраняют deadline/correlation и освобождают worker. Callback проверен по tenant/подключению/подписи, устойчивый receipt+outbox фиксируется до ACK; callback до ожидания, дубли/порядок и чужие callbacks обработаны.
- [x] Технические бюджеты глубины/итераций/параллелизма/объёма/времени и причинности не дают захватить весь worker; превышение объяснено и не отбрасывает ветви молча. Отключение/отмена останавливают новые эффекты, не прячут неизвестный результат.
- [x] Редактор и журнал полноценно работают со всеми блоками/ожиданиями по лично принятому baseline; права сверки/продолжения и очищенные данные сохраняют правила предыдущего результата.
- [x] Новый пользовательский сценарий, которого нет в пресетах, проходит несколько сервисов и составных блоков без правки ядра/общих экранов. Независимо написанный контрактный адаптер проверяет точки расширения в автоматических тестах; это не временный сетевой fake backend и не основание объявлять реальный сервис проверенным.
- [x] Тесты устойчивых ветвей/перебора/join, nested grants/recursion, callbacks до ожидания/дублей/чужой организации, падений и возобновления проходят. Затронутый UI проверен браузером в штатном контуре; справка всех блоков и примеры входят в результат.

## Заметки

Причина выделения: составное исполнение/корреляции и восстановление ветвей — отдельный большой законченный результат поверх уже проверенной опасной границы эффекта; объединение с lease/reconcile/журналом в предыдущую задачу слишком велико для одного bounded-сеанса. Это расширение одного runner, не отдельный workflow-продукт. Пути: execution/blocks.py и существующий runner/checkpoints, automation_events/ingress.py и callbacks, scenario_state/receipts.py/steps.py. C4: dynamic-blocks/event/recovery. Основа: SPEC-0037, ADR-0038, docs/service-integrations-c4.md и актуальный get_c4_context. Один backend/штатные PostgreSQL, worker/worker-events, inbox/outbox, tenant/RLS; без новых обязательных служб. Соблюдать AGENTS.md, DRY/KISS/SRP, NO GOD FILES, отдельные model/API/subviews, i18n ru/en. Проверки: сборка для изменений кода и только непосредственно затронутые тесты (backend --reuse-db), UI — браузером в штатном контуре. Без полного прогона, seed, временных API/fake backend и изменения доступов ради проверки. Для новых внешних доступов использовать реальный штатный контур; отсутствие доступа фиксировать как blocker, не выдавать непроверенное за пройденное. Перед submit_result прочитать get_c4_context, сверить реальные изменения со спецификацией/C4; необходимые изменения документации/архитектуры предложить единым propose_c4 и получить принятие, затем review_c4 с точным changeHash, затронутыми ID и доказательствами из кода. После изменения кода/документов повторить review. Planned не объявлять current до проверенной публикации.
