## Цель

При открытии ручного создания лида или контакта из диалога сразу показывать известные имя, email и телефон, сохраняя правки сотрудника. В справочнике ответственных Битрикс24 показывать полное доступное имя, затем email, и только при отсутствии обоих — ID.

## Критерии приёмки

- [x] Справочник Битрикс24 собирает доступное полное имя из NAME/SECOND_NAME/LAST_NAME, исключает пустые и пробельные части; при отсутствии имени использует EMAIL, при отсутствии имени/email — ID. Выбор и отправка операции сохраняют исходный ID сотрудника.
- [x] В ручном создании лида/контакта из доступного диалога имя, email и телефон текущего контакта сразу видны в соответствующих штатных полях; подстановка не требует сначала вводить значение, получать ошибку или запускать действие.
- [x] Сопоставление полей и типизированные преобразования явно объявлены адаптером; сервер выдаёт начальные значения отдельно от схемы. Общие серверные модули и UI не ветвятся по бренду и не угадывают назначение поля по его имени.
- [x] PHONE/EMAIL соответствуют вложенной схеме Битрикс24, сохраняют доступные в штатной модели известные значения без дублей. Частично заполненный контакт даёт только известные значения; неизвестные остаются пустыми. Фамилия не выводится из полного имени эвристикой; название, ответственный и стадия не выдумываются.
- [x] Сотрудник может изменить или очистить подставленное поле; preview, перезагрузка метаданных и получение справочников не затирают его ввод. Preview и запуск используют точные изменённые значения. При переходе к другому действию или диалогу данные предыдущего контакта не переносятся.
- [x] Подстановка не меняет контакт, права или внешние записи и не запускает операцию. Доступ к данным проверяется по актуальному сотруднику, организации и видимости диалога. Для изменения/удаления автоматически не применяются поля создания; явные привязки и параметры сохранённых сценариев сохраняют приоритет.
- [x] Пройдены только адресные тесты подписей справочника и затронутых контрактов/подстановки/сохранения ввода/изоляции; сборка затронутого приложения проходит. Backend-проверки с --reuse-db, без полного прогона. Изменённые файлы проверены на разделение ответственностей и NO GOD FILES.
- [x] Проведена browser-проверка штатного приложения на существующих данных и реальном backend: известные/частично известные контакты, изменение/очистка, смена контекста и справочник ответственных. Существующая компоновка baseline сохранена на desktop и в мобильном чате, в обеих темах. Ради проверки не создаются CRM-записи, mock API, seed-данные и аккаунты.
