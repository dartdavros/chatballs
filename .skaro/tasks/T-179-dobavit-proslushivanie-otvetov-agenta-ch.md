## Цель

Дать посетителю ручное прослушивание сохранённого AI-ответа с независимым TTS у агента. Сохранить текст, обычную переписку и повторное использование аудио только в памяти текущего виджета.

## Критерии приёмки

- [x] Использован лично принятый voice-design. У агента отдельные TTS-интеграция/модель при наличии/голос, у WEB — прослушивание. Пустой выбор выключает; нет скрытого наследования/автовключения/замены голоса или провайдера.
- [x] Backend принимает ID доступного окончательного AI-Message и проверяет origin/WebSession/актуальное согласие/функцию/организацию/клиентскую аудиторию. Произвольный текст браузера, чужое/операторское/внутреннее сообщение и незавершённый ответ отклоняются.
- [x] Синтезируется сохранённый plain text, включая оформленный ответ, без HTML/CSS/инструкций; история не изменяется. Длинный ответ соблюдает лимиты SpeechKit частями без потерь/перестановки/обрезания. Голос/язык совместимы, текст не переводится.
- [x] Реальный синтез запускается по нажатию; autoplay/pre-generation нет. Загрузка, запуск, pause/resume/repeat/stop и ошибки соответствуют baseline. Звучит один ответ, начало записи прекращает звук; геометрия ленты устойчива.
- [x] Single-flight/кэш текущего виджета по session/message/text/config revision исключают лишний синтез при повторе/параллельных нажатиях. Нет постоянного TTS-кэша/нового Message. Reset истории, смена сессии/настроек и unmount освобождают buffer/object URL; reload может требовать нового синтеза.
- [x] Ошибка TTS/голоса/языка/плеера оставляет ответ читаемым и ввод доступным, даёт повтор у ответа без передачи оператору/ложного готового состояния. Ключи/payload/полный TTS-текст не логируются; возможные персональные значения отражены в настройке/согласии.
- [x] Пройдены сборки затронутых приложений/образов и целевые тесты доступа/согласия/длинного текста/синтеза/кэша/cleanup/i18n, backend --reuse-db. В штатном приложении проверены настоящий SpeechKit TTS, длинный/оформленный ответ и повтор; справка/отчёт показывают фактический результат.

## Заметки

Причина выделения: прослушивание независимо полезно и имеет собственный контракт авторизации, синтеза/длинного текста и жизненного цикла звука. Зависимость voice-input переиспользует речевую регистрацию/routing, FFmpeg и общий consent; нет дробления на frontend/backend. Пути: speech/{synthesis,providers/yandex_tts}.py, webchat/{synthesis_views,speech_selectors}.py, ai/agent_models.py, internal-ui/features/agents/SpeechSettings.tsx, web-chat/src/speech/{useAnswerPlayback,AnswerPlayback}, ChatMessages.tsx. C4: code-speechkit-tts, code-web-synthesis, code-widget-playback, code-speech-config. Проверки входят в этот результат: для изменений кода сборка затронутых приложений/образов и только относящиеся тесты (backend --reuse-db), UI — браузером в штатном приложении. Полный тестовый прогон только по прямому указанию. Не создавать mock API/fake backend/временные HTTP-серверы/seed, не менять доступы. Отсутствие реального ключа/контура честно фиксировать blocker, не подменять успехом. Соблюдать AGENTS.md, DRY/KISS/SRP/NO GOD FILES, пределы компонентов ≈180–200 и файлов ≈300 строк, composition-only pages, существующие shared-компоненты/спиннер/.link/app-dropdown и ru/en t/tn/fmt. До сдачи get_c4_context и review_c4 по фактическому changeHash/reviewScope, affected IDs и code evidence; изменение поведения требует принятого C4-пакета. Planned не объявлять current до проверенной публикации. Не готовить спецификации или новые задачи в задаче реализации.
