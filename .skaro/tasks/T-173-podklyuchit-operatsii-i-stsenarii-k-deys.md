## Цель

Дать ИИ явно разрешённые действия интеграций и сценарии через существующий цикл инструментов. Самостоятельное выполнение, подтверждение сотрудника и долгий результат работают по одной политике с ручными запусками.

## Критерии приёмки

- [x] Обязательный gate: реализация начинается только после явно зафиксированной личной приёмки владельцем ОБОИХ результатов baseline; принятие карточки плана/задачи не является приёмкой макета. Основание: SPEC-0037 R-28.
- [x] Каталог доступных агенту операций/сценариев формируется из явных grants; текущий tool-loop вызывает общий launch/runner без второго бесконечного цикла, скрытой замены провайдера и доступа к произвольному tenant/секрету/связи сущностей.
- [x] Настройка агента, живой/проверочный чат и контекстное подтверждение соответствуют baseline. Запрет / самостоятельно / с подтверждением применяются к операции/сценарию; явно разрешённая запись/удаление могут выполняться самостоятельно, общего подтверждения всех записей нет.
- [x] Подтверждение привязано к точным параметрам/контексту/сроку, принимается текущим уполномоченным сотрудником и перепроверяется перед эффектом. Изменение параметров требует нового подтверждения; текст модели/события не считается согласием.
- [x] Описания/входы/результаты проходят штатную псевдонимизацию, известные значения раскрывает сервер только для исполнения; внешние результаты недоверенны, карта не сохраняется. Нет сырых промптов/ответов старых инструментов в операционном журнале.
- [x] Долгий запуск возвращает ID и фактическое состояние; после завершения заново проверяются режим организации, актуальный агент, управление диалогом и права до отправки. Отзыв/перехват исключают позднюю автономную отправку.
- [x] Проверочный чат различает проверку конфигурации и реальный изменяющий запуск без скрытой записи. Миграция, навыки и старые HTTP/MCP-разрешения сами не включают новые действия.
- [x] Тесты режима/отзыва/гонок подтверждения, маскирования, long-run/tool-budget и старого read-only контура проходят; UI проверен браузером, справка агентских действий входит в результат.

## Заметки

Причина выделения: законченный и независимо проверяемый способ запуска в существующем AI-runtime; его гонки управления диалогом и privacy существенно отличаются от ручного и автоматического пути. Он зависит от полного runner, но не требует ждать подключения автоматических триггеров. Пути: execution/ai_bridge.py, ai/{agent_tools,tool_loop,tool_calls}, UI features/agents/ и integrations/runs/. C4: dynamic-ai и соответствующие planned overlays. Основа: SPEC-0037, ADR-0038, docs/service-integrations-c4.md и актуальный get_c4_context. Один backend/штатные PostgreSQL, worker/worker-events, inbox/outbox, tenant/RLS; без новых обязательных служб. Соблюдать AGENTS.md, DRY/KISS/SRP, NO GOD FILES, отдельные model/API/subviews, i18n ru/en. Проверки: сборка для изменений кода и только непосредственно затронутые тесты (backend --reuse-db), UI — браузером в штатном контуре. Без полного прогона, seed, временных API/fake backend и изменения доступов ради проверки. Для новых внешних доступов использовать реальный штатный контур; отсутствие доступа фиксировать как blocker, не выдавать непроверенное за пройденное. Перед submit_result прочитать get_c4_context, сверить реальные изменения со спецификацией/C4; необходимые изменения документации/архитектуры предложить единым propose_c4 и получить принятие, затем review_c4 с точным changeHash, затронутыми ID и доказательствами из кода. После изменения кода/документов повторить review. Planned не объявлять current до проверенной публикации.
