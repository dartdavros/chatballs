## Цель

Один клиент для MCP и HTTP-инструментов с проверкой адресов после DNS, перенаправлений, размера и типа ответа; настройка установки разрешает частные диапазоны и хранит, кто и когда её включил (R-16–R-18).

## Критерии приёмки

- [x] Запросы на loopback, link-local, multicast, адреса и имена сервисов установки и частные диапазоны отклоняются после DNS-разрешения; соединение идёт на проверенный IP; перенаправлений не больше 3, каждое проверяется.
- [x] Ответ принимается только `application/json` или `text/*` и не больше 256 КБ; таймаут задаёт вызывающий.
- [x] `InstanceSettings` хранит признак «частные адреса для инструментов» (по умолчанию выключен), кто и когда включил; изменение пишется в журнал аудита; API установки отдаёт и меняет его только администратору установки.
- [x] При включённом признаке частные диапазоны разрешены, loopback и сервисы установки — нет.
- [x] Тесты: отказ внутренних адресов, перенаправление на внутренний адрес, превышение размера, доступ к настройке не администратора установки.

## Заметки

Переиспользовать `integrations/outbound.py` (`_resolves_to_private`, `OutboundUrlRejected`); для LLM-провайдеров правила не менять.

## Итог

Добавлен единый исходящий клиент инструментов агента (integrations/tool_client.py) с политикой адресов (integrations/tool_network.py): проверка IP после DNS, соединение с проверенным IP, до 3 проверяемых перенаправлений, ответ только application/json или text/* до 256 КБ, срок от вызывающего. В InstanceSettings появился признак «частные адреса для инструментов» с тем, кто и когда включил; API instance/settings/tools-network/ доступен только администратору установки, изменение пишется в журнал аудита. Правила для LLM-провайдеров не менялись (тесты outbound прошли); интерфейса настройки в этой задаче нет — только бэкенд.
