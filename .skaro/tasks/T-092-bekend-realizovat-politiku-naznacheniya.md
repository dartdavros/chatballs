## Цель

Реализовать политику выбора получателя, атомарную передачу с уведомлением и защищённое чтение её истории.

## Критерии приёмки

- [x] Настройки явно задают разрешённые статусы назначения и проверяются сервером.
- [x] Справочник получателей раздельно выдаёт присутствие, рабочий статус и нагрузку без утечки чужих сотрудников.
- [x] Неактивный, блокированный или запрещённый политикой получатель отклоняется без изменения диалога.
- [x] Смена ответственного, журнал, доменное событие и уведомление образуют одну логическую операцию.
- [x] Конкурентная версия и повтор ключа не перезаписывают новую передачу и не создают дубль.
- [x] Получатель получает защищённое уведомление; причина и комментарий не уходят клиенту или в AI.
- [x] API выдаёт пагинированный журнал только по действующему доступу к диалогу.
- [x] Снимок отключённой либо переименованной причины читается в исходном виде.
- [x] Прямой идентификатор, чужой tenant и потеря доступа не раскрывают комментарий.

## Заметки

Основание границ задачи: Политика назначения, переход и журнал составляют один серверный сценарий. Готовый API нужен рабочему чату и может выполняться независимо от ещё не утверждённых UI-макетов.
