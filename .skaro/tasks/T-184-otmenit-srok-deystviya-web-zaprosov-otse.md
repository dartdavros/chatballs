## Цель

Сделать оценку из веб-виджета доступной независимо от времени после отправки, включая уже отправленные и ранее просроченные запросы. Устранить ситуацию, когда посетителю показывается предложение оценить, но форма или отправка отклоняются как просроченные.

## Критерии приёмки

- [x] WEB-запрос оценки и прежний credential принимаются независимо от возраста: новые, доставленные до обновления и ранее истёкшие по семидневному TTL запросы работают, если не отменены и данные существуют. Увеличение TTL на большой конечный срок не считается исправлением.
- [x] Семидневная проверка убрана согласованно из delivery/session_requests, resolved_request/API и SQL-функций/триггеров/защищённого rating_request_directory. Добавлены штатные миграции; уже применённые миграции не переписываются.
- [x] Миграция сохраняет существующие credential, связи с завершением/диалогом, снимки шкал, времена отправки, результаты и отмены. Аккаунты/сессии/права не меняются; запросы не переотправляются, дубликаты оценки/событий не создаются.
- [x] API/TypeScript-контракт достоверно представляет отсутствие expiresAt либо его бессрочное значение; сериализация, handoff, poll и клиентская форма не требуют конечной даты и согласованы друг с другом. Фиктивная дата в далёком будущем не используется.
- [x] Карточка и форма корректно работают при долгом открытии вкладки, открытии старого предложения и после перезагрузки. Время само по себе не переводит запрос в состояние просрочки; несуществующий, отменённый или удалённый запрос остаётся недоступным с корректным существующим состоянием/локализованным объяснением.
- [x] Сохраняются непредсказуемость и хеширование credential, RLS/изоляция организации, привязка к одному запросу, rate limits и запрет чтения истории. Другие каналы и общие таймауты/сроки сессий не расширяются этим изменением.
- [x] Одна оценка остаётся атомарной и неизменяемой: повтор той же отправки возвращает результат даже спустя прежние 7 дней; попытка заменить значение получает конфликт. Существующие результаты не обнуляются и не пересчитываются.
- [x] Целевые backend-тесты с --reuse-db покрывают запросы старше 7 дней, старые credential после миграции, directory/SQL guards, отмену/удаление/изоляцию, повтор и конфликт; проверены необходимые клиентские сценарии/контракты. Выполнены сборка затронутых приложений и штатная browser-проверка; полный прогон не запускается.

## Заметки

Покрывает последнее замечание владельца о просроченной оценке. Самостоятельная группа — сквозное изменение жизненного цикла запроса и ограничений БД; миграции, API, UI и проверки должны входить в одну задачу, чтобы нельзя было поставить только маскировку ошибки. Независима от двух UI-задач. Причина подтверждена: ratings/web_delivery.py REQUEST_TTL=7 days, public_service.py expires_at__gt, migrations/0002_guards.py — требование sent_at+7 days, guard_customer_rating и view directory; web-chat/ratings/useRating.ts переводит 404 в expired. Обновлять docs по существующему паттерну без новой задачи планирования. Не отменять предусмотренные удаление/отзыв; «никогда не просрочено» означает отсутствие временного срока. Не проводить production-миграцию/деплой в этой задаче. Работать только в штатном контуре, без mock API/fake backend/временных HTTP-серверов/seed/смены учётных данных и реальных прав ради проверки. Новые строки — ru/en i18n, t/tn/fmt. Соблюдать DRY/KISS/SRP и ограничения NO GOD FILES; изменённые файлы проверить по размеру и ответственности. Сборка — по правилам владельца (для мелких локальных CSS/текстовых правок автоматически не запускать); только тесты изменённого поведения, backend с --reuse-db, без полного прогона. Для UI обязательна browser-проверка с реальным backend. Перед реализацией необходим принятый пакет skaro-c4-358626c8-fcc5-4d68-aa19-9f992e546180 и проверка get_c4_context; pending не является принятой спецификацией. При реализации — C4-review только фактического affected scope. Production/deployment не менять.
