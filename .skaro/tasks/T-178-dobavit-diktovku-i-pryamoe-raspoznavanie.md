## Цель

Реализовать законченный путь записи до редактируемого черновика и обычной отправки, сохранив голосовые сообщения. Подключить прямой STT и единый серверный consent для речи и будущего события сайта.

## Критерии приёмки

- [x] До нового UI явно зафиксирована личная приёмка voice-design. Режим off/voice_message/dictation, maxRecordingBytes и maxDictationSeconds хранятся в WEB; миграция сохраняет прежние разрешения, новые функции выключены. Defaults: 10 МиБ, диктовка 60 секунд; значения валидируются, публичны эффективные возможности.
- [x] SpeechKit зарегистрирован отдельной речевой интеграцией с зашифрованным ключом/каталогом/проверкой STT. Capability-контракт/routing сохраняют прежние совместимые STT, наследование пустого выбора и provider-aware defaults. Нет SpeechKit в chat/embeddings, whisper-1 для него или fallback при неисправном явном выборе.
- [x] Общий webchat/consent.py сохраняет версию/время актуального согласия WebSession после серверной валидации обязательной формы. Старый token/localStorage не доказывают согласие; речь проверяет его до I/O. Реализация предоставляет единый повторно используемый guard для voice-output и site-proactive.
- [x] MediaRecorder корректно обрабатывает разрешение/отмену/остановку и прекращает запись по первому пределу; нет одновременного проигрывания. Backend независимо проверяет байты/формат/декодированную длительность и не доверяет duration/MIME.
- [x] WebM/Opus, Ogg/Opus и доступный браузеру MP4 обрабатываются FFmpeg через ограниченные pipes без shell/постоянного файла. FFmpeg установлен в dev/production backend-образах; новая служба/бакет/ручная настройка хоста не нужна.
- [x] STT v3 inline content реально распознаёт 60-секундную запись с bounded polling/cleanup внешнего результата, вне DB-транзакции. Нет аудио/черновика в истории/постоянном хранилище/очереди/логах, буферы освобождаются. Политика внешней обработки честно описана.
- [x] Результат одной попытки дополняет актуальный черновик без потери правок во время ожидания; отменённый/устаревший ответ не применяется. Текст можно исправить/удалить, превышение длины не обрезается. Только явная обычная отправка создаёт текстовое Message; STT сам не создаёт Conversation/AI/обращение.
- [x] При сбое/пустой речи доступны повтор доступной записи/отмена/обычный ввод, текст сохраняется. Отправленное голосовое сохраняет запись и прежний путь передачи оператору при неудачном STT, включая SpeechKit; остальные лимиты каналов не меняются.
- [x] Пройдены сборки затронутых приложений/образов и целевые тесты маршрутизации/consent/формы/лимитов/черновика/tenant/voice/i18n, backend --reuse-db. В штатном браузере проверена настоящая диктовка через SpeechKit, в том числе 60 секунд; справка/отчёт содержат фактические результаты и ограничения, без заглушек.

## Заметки

Причина выделения: диктовка/STT — самостоятельно полезный пользовательский результат, поставляемый до TTS. Настройки, миграции, frontend/backend, нормализация, безопасность, тесты и справка остаются вместе, не разбиты по слоям. Эта задача единственная создаёт общую серверную модель consent; межэтапная зависимость исключает дублирующие миграции. Пути: chatballs/speech/{contracts,routing,configuration,formats,providers/yandex_stt}.py; webchat/{dictation_views,consent,sessions,configuration}.py; ai/{agent_models,provider_selection}.py; conversations/transcription.py; internal-ui/features/{agents,integrations}; web-chat/src/speech/, useVoiceRecorder.ts, ChatComposer.tsx; packages/contracts; backend Dockerfile/Dockerfile.production. C4: component-speech, code-speech-contracts/config/formats, code-speechkit-stt, code-web-dictation/consent, code-widget-dictation. Проверки входят в этот результат: для изменений кода сборка затронутых приложений/образов и только относящиеся тесты (backend --reuse-db), UI — браузером в штатном приложении. Полный тестовый прогон только по прямому указанию. Не создавать mock API/fake backend/временные HTTP-серверы/seed, не менять доступы. Отсутствие реального ключа/контура честно фиксировать blocker, не подменять успехом. Соблюдать AGENTS.md, DRY/KISS/SRP/NO GOD FILES, пределы компонентов ≈180–200 и файлов ≈300 строк, composition-only pages, существующие shared-компоненты/спиннер/.link/app-dropdown и ru/en t/tn/fmt. До сдачи get_c4_context и review_c4 по фактическому changeHash/reviewScope, affected IDs и code evidence; изменение поведения требует принятого C4-пакета. Planned не объявлять current до проверенной публикации. Не готовить спецификации или новые задачи в задаче реализации.
