## Контекст

Клиенты спрашивают то, чего нет в базе знаний: статус своего заказа, наличие и цену товара, подбор под параметры. Ответ есть только в системах организации — на сайте, в учётной системе, в каталоге. Без доступа к ним агент передаёт такие вопросы оператору.

ADR-0019 и бриф исключают из продукта заказы, каталог и продажи как собственные данные Chatballs. Агент, который спрашивает систему организации и пересказывает ответ, этих данных не хранит.

Силы:
- запуск за минуты: у многих сайтов нет MCP-сервера, но есть REST API;
- MCP — открытый стандарт подключения инструментов к моделям;
- данные с сайта недоверенные (ADR-0030): номер заказа может подменить любой;
- персональные данные не должны уходить в модель (ADR «Согласие клиента и псевдонимизация персональных данных для LLM»);
- установка обслуживает несколько организаций: исходящий запрос не должен достигать внутренней сети установки;
- ход AI ограничен сроком и выполняется в `worker-events` (ADR-0028).

## Решение

1. Инструменты подключаются интеграцией организации «Внешний сервер» двух видов:
   - MCP-сервер по Streamable HTTP: адрес и заголовки авторизации. Список инструментов получается из `tools/list` по кнопке «Обновить» и хранится снимком;
   - HTTP-запрос: имя, описание для модели, метод `GET` или `POST`, шаблон адреса, параметры со схемой, заголовки.

   Секреты хранятся в зашифрованных полях, как у других интеграций.
2. Агенту инструменты включаются явно в карточке агента. Без включённых инструментов ход не меняется.
3. В первой версии инструменты только читают:
   - HTTP-запрос: `GET`, а `POST` — только с явной отметкой администратора «только чтение»;
   - MCP-инструмент включается, если сервер отметил его `readOnlyHint`, или администратор подтвердил это сам.

   Для нового сервисного контура изменяющие действия определены ADR-0038/SPEC-0037: отдельные явные разрешения, общий исполнитель, самостоятельное выполнение либо подтверждение по настройке. Самостоятельные инструменты этого ADR сохраняют прежнюю read-only-политику; миграция её не снимает.
4. Ход использует вызов инструментов OpenAI-совместимого API (`tools`, `tool_calls`):
   - не больше 5 раундов вызовов и не больше 30 секунд на вызов, всё — в пределах срока хода;
   - просрочка и ошибки передают диалог оператору по действующим правилам;
   - демо-провайдер имитирует вызов детерминированно.
5. Аргументы и результаты проходят слой псевдонимизации:
   - токены в аргументах сервер раскрывает перед вызовом;
   - параметр инструмента можно привязать к полю контакта или к своему полю — тогда его подставляет сервер, а модель его не передаёт;
   - результат маскируется перед возвратом в модель и подаётся как данные, а не инструкции.
6. Исходящие запросы не идут на loopback, link-local, адреса и имена внутренней сети установки и частные диапазоны. Частные диапазоны может разрешить администратор установки. Перенаправления проверяются тем же правилом. Ответ — не больше 256 КБ, только JSON или текст.
7. Для самостоятельного read-only-контура каждый вызов пишется в ленту диалога системным событием с кодом: инструмент, успех или ошибка, длительность. Аргументы и ответы в базе и журналах не хранятся.
8. Авторизацию данных обеспечивает система организации: данные с сайта подменяемы, поэтому API не должен отдавать чужие сведения по одному номеру. Это описывается в справке.

9. Минимальное устойчивое операционное состояние сервисного контура хранится по ADR-0038/SPEC-0037 и не является разрешением хранить сырые ответы старых инструментов/карту псевдонимов. Сетевая политика, недоверенность результатов, ограничения доступа и маскирование сохраняются; файлы/большие данные новых операций обрабатываются отдельным типизированным контрактом общего транспорта.

## Последствия

Плюсы:
- агент отвечает на вопросы о заказах, наличии и ценах и готовит подборки и коммерческие предложения текстом в чате, а Chatballs не хранит коммерческих данных;
- MCP даёт стандартное подключение, HTTP-запрос — подключение существующего REST за минуты;
- ПДн из ответов систем до модели не доходят.

Минусы и риски:
- нужна модель с поддержкой вызова инструментов: у части моделей OpenRouter и у части OpenAI-совместимых endpoint её нет. Карточка агента должна это сообщать;
- ход дольше и дороже: несколько обращений к модели за один ответ;
- результат инструмента — канал prompt injection. Смягчение — подача как данных, только чтение, ограничение размера;
- подменённый номер заказа может раскрыть чужой заказ, если API сайта не проверяет владельца. Ответственность сайта, которую нужно объяснить в справке;
- новый тип интеграции и защита от SSRF требуют тестов изоляции и сетевых проверок;
- бриф и архитектуру нужно дополнить: «агент обращается к системам организации через инструменты» — граница ADR-0019 не меняется.
