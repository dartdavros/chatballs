# Ручные действия в рабочем чате

## Проблема и принятое к согласованию изменение
В текущем коде ManualActionMenu выводит titles из полного run-actions каталога, а ContactActions повторяет это же меню в карточке контакта. Native manual_actions выдаёт менеджеру весь tenant-каталог; общий menu.css ожидает button-разметку, которой в пунктах нет. Это объясняет административные операции и неоформленные строки. Данный пакет описывает план исправления, а не выполненную реализацию.

По указанию владельца от 05.11.2026 запуск остаётся в одном месте — шапке диалога. Основание оформления — design/baseline/service-integrations/Запуск из диалога.dc.html, кадр L1; прямое изменение владельца отменяет блок запуска в карточке контакта и его пустое состояние. Остальной визуальный язык baseline сохраняется.

## Состав и права
Сервер формирует отдельную проекцию рабочего меню. В неё входят включённые сценарии с ручным staff-триггером и областью conversation/contact, а также операции существующих SERVICE-подключений в доступном рабочем контексте. OWNER/ADMIN видят этот набор; оператор — разрешённую часть по текущим правилам сотрудников/групп, ActionGrant и видимости диалога. Проверяются применимость контекста и наличие контакта, когда он обязателен.

Сценарии общей организационной области и сырые native API-команды в рабочем меню отсутствуют у обеих ролей. Полный NativeAction-реестр и его API-покрытие сохраняются для редактора/исполнителя; необходимые встроенные действия могут входить в явно включённый контекстный сценарий. Это фильтр назначения UI, не отзыв полномочий и не новая система ролей. Preview/launch/effects повторно проверяют текущие права прежним механизмом. Общий каталог редактирования сценариев и редактор прав ИИ не ограничиваются проекцией меню.

Число пунктов динамическое. Например, четыре настроенных действия дают администратору четыре пункта, а оператору с разрешением на два — два; это пример, не нормативные числа. Нулевой набор скрывает кнопку без пустого блока в контакте. Техническая недоступность разрешённого пункта сохраняет строку с причиной и запретом запуска; отсутствие разрешения не расширяет выдачу.

## Вёрстка
В существующей строке шапки остаётся Button с имеющимся Icon plug. Открытие — antd Dropdown с overlayClassName app-dropdown, закрытие по Esc/вне и портал штатные. Геометрия desktop из L1: 340 px, padding 5 px, radius 10 px; строка с padding 8/10 px, gap 10 px, область существующей иконки 28 px, radius 7 px. Название 13 px/600, пояснение 11.5 px, цвета/темы через действующие токены. Заголовок меню — «Доступно в этом диалоге».

Высота ограничена доступным окном, длинный список прокручивается внутри; подписи переносятся без наложений. Мобильная шапка и панель запуска используют существующий baseline и компоненты, второй вход не появляется. Причина недоступности видна под названием, а не только в title. Все продуктовые подписи — через i18n; служебные ключи не отображаются.

ContactActions перестаёт владеть запуском; ContactEntityLinks размещается отдельно прежним компонентом. Выбор действия открывает существующий workflow параметров/preview/подтверждения и журнал, без нового runtime.

## C4 и применимость уровней
Контекст и контейнеры используют прежние view-service-context и view-service-containers: сотрудник, та же React-сборка, HTTP API Django. Компоненты покрыты view-service-workbench и действующим backend; код — отдельной проекцией manual catalog и существующим UI runs. Упорядоченная динамика описывает загрузку контекста, отбор каталога, показ одного меню, preview/launch и повторную авторизацию. Deployment использует view-service-deployment: новых процессов, узлов, портов, хранилищ и миграции данных изменение не требует (compose.yaml, compose.dev.yaml). Новые связи/изменённые обязанности остаются planned до проверки публикации.

## Объём проверки
Целевые проверки API: администратор/оператор, staff-триггер и область сценария, отсутствие административного native-каталога, архив/нет контакта/нет разрешения, сохранение полного редакторского реестра и повторной авторизации запуска. UI: ровно один вход; связанные записи сохранены; доступная/недоступная строка, длинная подпись и прокрутка, пустой набор; desktop 1024/1440, мобильный чат и обе темы. Проверки — в штатном backend/frontend без seed/mock; недоступность browser-проверки явно блокирует объявление UI готовым.

## Вне изменения
Новый каталог настройки видимости операций, новые бизнес-действия, выдача/отзыв прав, изменение исполнителя, новая карточка контакта и административный мобильный UI не входят в исправление. Два существующих C4-вопроса про облачные звонки и режим CLI к этим ID не относятся.
