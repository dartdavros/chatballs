# T-151: согласованные исключения из макета правил обработки

Решение владельца от 14.10.2026 в проектном чате: «Сохранить действующий backend: убрать неподдерживаемое условие и обещание удаления, исправить текст о версии; остальной макет сохранить».

## Источник дизайна

`design/baseline/platform-expansion/Настройки · новые разделы.dc.html`, кадры N14–N15. Сохраняются структура, порядок разделов и полей, компоненты, визуальный язык и все остальные состояния утверждённого baseline. Исходный экспорт дизайна не переписывается.

## Три согласованных исключения

1. Не показывать условие «Рабочее время организации»: бизнес-календаря нет в действующем API, он исключён из SPEC-0034. Доступные условия берутся только из штатного серверного каталога. Не заменять календарь рабочей доступностью: это разные условия.
2. Не показывать обещание «события старше 90 дней удаляются». Штатный backend не реализует такое удаление. Остальные сведения о количестве и фильтрах журнала сохраняются и берутся из API.
3. Заменить обещание выполнения ожидающих действий по прежней версии правила текстом «Изменение правила создаёт новую версию; ожидающие действия по прежней версии отменяются». Это соответствует SPEC-0034 R-4 и проверке актуальной версии исполнителем. Уже отправленные сообщения не удаляются.

## Границы изменения

Решение не расширяет спецификацию, не добавляет календарь, автоудаление журнала или новый способ исполнения правил. Серверное поведение, сроки, условия и права сохраняются. Все пользовательские строки размещаются в русских и английских словарях; внутренние коды и служебные пояснения не выводятся в UI.

Реализация T-151, необходимые адресные тесты, сборка и браузерная проверка штатного контура входят в существующую задачу. Дополнительные задачи подготовки или планирования не создаются.
