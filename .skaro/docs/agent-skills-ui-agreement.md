# Навыки агентов: согласованное дополнение UI

## Основание и статус

15.10.2026 владелец разрешил использовать существующие компоненты Chatballs для состояний, отсутствующих в двух предоставленных макетах, и поручил определить точный перечень до UI-задач. Готовый навык устанавливается по действию администратора, без автоматического подключения инструментов и изменения внешних данных.

Документ конкретизирует это разрешение. Показанные кадры K1–K6/T1–T4/A1–A3/W1–W4/F1–F3 сохраняются. Дополнения ниже — явно учтённые отклонения от неполного baseline; coding-агент не расширяет их самостоятельно.

## Используемые элементы

- `shared/form-controls.tsx`: FormField, TextAreaField, SelectField, SwitchButton.
- `shared/ui-controls.tsx`: Button, BackLink, существующий SelectMenu.
- `shared/ui.tsx`: Segmented, EmptyState, ErrorScreen, LoadingState, PermissionScreen.
- `shared/Pagination.tsx`: единый подвал списка.
- antd Modal для подтверждений и редактирования поля; antd Dropdown с app-dropdown и row-menu-button для меню.
- `shared/links.css`: только общий стандарт ссылок.
- `features/integrations/site-fields/FieldDialog.tsx` — композиция диалога поля как образец, без переноса модели site fields, aiAccess и её семантики.
- `features/reply-templates/ReplyTemplateForm.tsx` — обработка ошибок формы как образец; ручные шаблоны не объединяются с шаблонами навыков.
- `features/agents/test-chat/TestChatFeed.tsx` — существующая оболочка проверочного чата.

Повторяемую композицию разрешается вынести в малый общий компонент. Нельзя копировать крупную страницу, заменять систему компонентов собственными меню или смешивать пользовательские шаблоны с исполняемым кодом.

## Точный перечень дополнений

| Пробел | Решение |
|---|---|
| Создание навыка | Действие K1/K2 открывает тот же редактор K5 с пустыми полями и отсутствующими шаблонами. До первого сохранения объекта в БД нет. Наверху формы только при создании SelectField «Основа»: «С нуля» / «Работа с заказами». Выбор готового варианта заполняет локальную форму инструкцией и двумя шаблонами. Если форма уже изменена, смена основы сначала подтверждается Modal «Заменить введённые данные?» с «Отмена» / «Заменить». |
| Установка готового навыка | Это сохранение выбранной основы в новую обычную конфигурацию организации; действие «Создать навык». Никаких автоматических подключений к агентам, интеграций, включения инструментов или seed. Сбой сохраняет форму, повтор одного запроса не создаёт дубликат. После сохранения открывается обычный K5; подключение агентам — A2. |
| Новый шаблон | «Добавить шаблон» открывает T1 с пустыми названием/назначением, схемой и исходниками; образцы заказа не подставляются молча. Обязательная текстовая версия должна быть заполнена перед сохранением. |
| Входные поля | Кнопка «Поле» открывает antd Modal по композиции FieldDialog: «Добавить поле» / «Изменить поле»; FormField «Имя поля», TextAreaField «Описание», SelectField «Тип» со значениями «Строка», «Число», «Логическое значение», «Объект», «Список»; SwitchButton «Обязательное»; для списка SelectField «Тип элемента» с теми же типами; SelectField «Родитель» для выбора корня, объекта либо объекта-элемента списка. Действия «Отмена» / «Сохранить». |
| Вложенные поля | Показываются в левой колонке T1 с отступом, как items/title в макете. Родителя выбирают из уже созданных объектных узлов; циклы и недопустимая глубина отклоняются. Список скаляров не имеет дочерних полей; вложенный список описывается теми же контролами, без нового визуального конструктора. |
| Изменение/удаление поля | В строке поля меню Dropdown «Изменить» / «Удалить». Смена имени/типа не переписывает исходники автоматически: общая валидация покажет старые ссылки. Удаление объекта/списка подтверждается Modal с предупреждением об удалении дочерних полей. Внесённые изменения остаются локальными до сохранения конфигурации. |
| Вкладка CSS | Та же центральная колонка и кодовый редактор, что у HTML в T1; активен CSS. Ошибки и строки — точно по композиции T2. Никакой отдельной страницы, live-исполнения и визуального конструктора. |
| Пример данных | Редактируемый JSON в существующей правой колонке T1. Именованные примеры готовы у поставляемого навыка; у нового шаблона один редактируемый пример. Смена примера не меняет бизнес-настройки. Серверный предпросмотр обновляется после короткой задержки ввода; устаревший ответ не заменяет актуальный. |
| Ошибка загрузки | ErrorScreen с существующим повтором, в области содержимого, сохраняя навигацию. Загрузка библиотеки — K3; загрузка карточки — LoadingState. |
| Объект не найден | EmptyState «Навык не найден» / «Шаблон не найден» и существующий BackLink к библиотеке/навыку. Прав нет — PermissionScreen. |
| Пустой поиск | В области таблицы EmptyState «Ничего не найдено»; строка поиска остаётся. Очищается штатным действием поля поиска, без дополнительной карточки. |
| Ошибка сохранения/подключения/удаления | Существующая форма/Modal остаётся открытой, введённое и выбор сохраняются; ошибка в стиле K6 и доступен повтор того же действия. Никакого ложного успешного уведомления. |
| Конкурентная правка | Баннер ошибки по K6: «Навык изменён другим сотрудником. Обновите данные перед сохранением». Существующая вторичная Button «Обновить данные» вызывает Modal «Заменить введённые данные?»; без согласия локальный ввод остаётся. Автоматического слияния или перезаписи нет. |
| Несохранённое | Modal T4 применяется к уходу из редактора навыка/шаблона и смене основы. Для штатной навигации «Не сохранять» / «Остаться» / «Сохранить»; закрытие вкладки использует стандартное предупреждение браузера, если оно поддерживается. |
| Совместимость модели | Под блоком «Навыки» и в существующей панели проверки — предупреждение в уже используемом стиле AgentToolsCard/ModelCard: «Эта модель не поддерживает навыки. Выберите модель с поддержкой вызова инструментов». Подключённые навыки остаются в списке. Неизвестная совместимость показывается как неизвестная, не как подтверждённая ошибка или успех. |
| Текстовая версия F1/F3 | Действие раскрывает сохранённый текст непосредственно под карточкой в том же пузыре; подпись меняется на «Скрыть текстовую версию». Используются button.link.is-muted и существующие текст/отступы пузыря; отдельного окна нет. F2 сразу показывает текст. |
| Проверочный чат | Сохраняется оболочка TestChatFeed; вместо строки ответа общий безопасный renderer. Обычные ответы и ошибки остаются как раньше. Новые плашки внутренних операций навыка не добавляются. |
| Расширенная карточка агента | Блок A1 после InstructionsCard в левой колонке, до KnowledgeCard. Уже существующие знания, помощь, подключения, модель и инструменты не удаляются и не переставляются. |
| Ширина администратора | Сохраняется трёхколоночная структура T1 в доступной ширине с гибкими колонками; минимум 1024 по SPEC-0015. Строки кода могут прокручиваться внутри редактора, но карточка предпросмотра и приложение не получают горизонтальный скролл. Мобильную административную страницу не создают. |
| Изменённый шаблон F3 | Если исходный шаблон существует и его техническая ревизия новее сохранённой, показывается пояснение F3. Если шаблон удалён, карточка всё равно читается из снимка; придуманной плашки удаления нет. Прочитать библиотеку клиенту ради этого нельзя. |

## Граница сохранения

Навык вместе с шаблонами — одна атомарно сохраняемая конфигурация.

K5 и T1 работают с общим локальным набором изменений. «Сохранить»/«Создать навык» в редакторе навыка сохраняет весь набор; «Сохранить шаблон» в T1 также сохраняет весь текущий набор конфигурации навыка, а не частично применяет дочерний объект. Если имеются изменения вне текущего шаблона, под действием показывается: «Будут сохранены и изменения навыка». Это явное дополнение к макету снимает двусмысленность K5/T4.

При незаполненных обязательных полях навыка сохранение из шаблона показывает ошибки и возвращает к соответствующим полям; введённый шаблон не теряется. «Не сохранять» отбрасывает весь набор при выходе из навыка; при возврате из шаблона к навыку оставляет набор локальным и не публикует. «Сохранить» в T4 применяет тот же атомарный контракт; при ошибке уход не происходит.

Шаблоны имеют стабильные идентификаторы после сохранения; новые объекты до сохранения могут использовать локальные ключи только внутри UI. Все повторные сохранения/установка защищаются идемпотентностью запроса и ожидаемой ревизией.

## Язык и границы текстов

Все перечисленные новые системные подписи проходят t/tn с RU/EN. Названия полей схемы и код — пользовательские данные, не переводятся. Технические коды ошибок, ревизии, типы API, ссылки на внутренние документы и номера кадров на экран не выводятся.

Готовый пример локализуется при установке по языку организации: системные названия/подписи и примеры RU/EN, инструкция для модели по правилам проекта. После установки это пользовательский текст и автоматически вслед за сменой языка не переписывается.

## Проверка

До признания UI готовым требуется browser-проверка перечисленных состояний в штатном приложении, обеих тем и размеров из baseline. Исходный HTML пока изучен по структуре и данным кадров; визуальный браузерный просмотр в этой сессии недоступен. Это ограничение не считается успешной проверкой приложения.
