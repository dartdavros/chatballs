Расширение по документу «Функциональные требования к расширению платформы» от 06.10.2026 описывает целевое, ещё не реализованное поведение. Новые полномочия и структуры реализуются после принятия соответствующих спецификаций и ADR; новый UI — после утверждения baseline.

Уточнение для двух режимов организации — целевое поведение по спецификации «Режим работы организации: с ИИ-агентами или только операторы»; само изменение документа не означает готовность реализации. По прямому уточнению владельца UI этого изменения использует существующие компоненты и паттерны; отдельное дополнение макета не требуется, новый дизайн не вводится.

## Problem

Агент — конфигурация AI-собеседника и центр управления его поведением. Подключения могут работать без агента в операторском режиме; внутренний маршрут обработки при этом сохраняется. Администратор должен настраивать его на одной карточке, а ответ клиенту — приходить вовремя и не блокировать другие каналы. Основания — ADR-0009, ADR-0029, ADR-0028, ADR-0002.

## Scenarios

1. Администратор создаёт агента мастером из одного шага; остальное настраивает в карточке.
2. В карточке выбирает провайдера и модель ответов, отдельно — провайдера и модель расшифровки голосовых, размер контекста, группу; видит подключения и код виджета.
3. Проверочный чат карточки отвечает с тем же окном истории, что и живой диалог.
4. Клиент пишет в мессенджер — приём записывает сообщение, ход AI считается отдельно; пока идёт ход, виджет показывает «печатает».

## Requirements

- R-1. Карточка реального агента — центр администрирования его AI-конфигурации: имя и статус, группа (необязательна), инструкции, модель, знания и статьи (только чтение состава — SPEC-0013), связанные подключения со статусом, код вставки виджета, дневной лимит стоимости. Подключения могут управляться самостоятельно в настройках; создание операторского подключения не создаёт AIAgent.
- R-2. Инструкции — три поля: Персонализация, Тон общения, Инструкции. Системный промпт: Персонализация → Тон → Инструкции → каталог материалов (знания со ссылками вложений и статьи с адресом Help Center); содержимое подтягивает retrieval. Системный промпт не переводится; язык ответа задаёт директива по полю `answer_language` (по умолчанию — как у клиента).
- R-3. Ответы, распознавание и озвучивание независимо настраиваются у агента по SPEC-0039/ADR-0039. Прежние провайдер+модель ответов/STT сохраняют наследование пустой модели; пустой STT-провайдер — как у ответов при поддержке способности. Default STT задаёт адаптер (whisper-1 для прежнего совместимого). TTS отдельно выбирает интеграцию/модель при наличии/голос; пусто выключает, скрытого наследования нет.
- R-4. Размер контекста — число последних сообщений диалога для модели: 1–200, по умолчанию 20, в блоке «Модель». История выбирается в базе с ограничением.
- R-5. Изменения агента применяются сразу, без публикации, но статус агента не обходит режим работы организации. В режиме «Только операторы» сохранённые конфигурация и статус агента не дают права на автономный ответ.
- R-6. Ход AI выполняется в `worker-events`, ходы одного диалога — строго по очереди; ответ ограничен сроком — просрочка передаёт диалог оператору с понятным текстом клиенту.
- R-7. Ошибка расшифровки показывается оператору фразой «что случилось и где чинить», без ответа чужого API.
- R-8. Список агентов: имя, группа, статус, подключения, счётчик открытых диалогов. Количество агентов не ограничено.
- R-9. Мастер создания агента знания не выбирает.

- R-10. Помощь оператору включается независимо от самостоятельных ответов агента. Черновик и альтернативы используют настройки провайдера, модели, инструкций, знаний и языка агента, но не отправляются клиенту и не меняют управление диалогом. Подробный контракт — спецификация «ИИ-черновик ответа оператору».
- R-11. Отдельный анализ качества завершённых обращений не является автономным ответом и не включается вместе с агентом автоматически. Критерии, версии результата и корректировки задаёт спецификация «ИИ-анализ качества обслуживания».
- R-12. Внутренние комментарии и причины передач исключаются из контекста автономного ответа, помощи и анализа до отдельного принятого изменения. Отбор аудитории выполняется до лимита истории; все AI-вызовы проходят SPEC-0022.

- R-13. Агенту явно подключаются общие навыки организации по SPEC-0035/ADR-0036. В начальный контекст входит краткий каталог; подробная инструкция и назначения/схемы шаблонов загружаются внутренней операцией по выбору модели. Навык не добавляет инструментов и не меняет системные ограничения, язык и передачу человеку. Конфигурация навыков для одного хода согласована; следующие ходы получают сохранённые изменения.
- R-14. Живой и проверочный чат используют один механизм навыков, общего срока, псевдонимизации и ограниченного цикла вызовов. Несовместимая с вызовами инструментов модель явно обозначается; скрытая подстановка всех инструкций вместо загрузки запрещена.
- R-15. Окончательный ответ может быть оформленным снимком по SPEC-0035: модель выбирает шаблон и данные, сервер собирает текст/HTML/CSS, сохранение и доставка остаются в штатном контуре. История для AI использует текст с новой псевдонимизацией. Применение навыков не включается автоматически в помощь сотруднику или анализ качества.
- R-16. Блок «Навыки» и управление ими реализуются по новому baseline и точному дополнению UI SPEC-0035, сохраняя существующие знания, помощь, подключения и инструменты карточки.

- R-17. Автономная работа разрешается общей серверной политикой согласно спецификации «Режим работы организации: с ИИ-агентами или только операторы»: режим организации с агентами, подходящий активный агент и допустимое состояние подключения/маршрута/диалога. Операторский маршрут не требует AIAgent; ensure-поведение при чтении или настройке такого подключения запрещено. Переключение инвалидирует незавершённые ходы по версии режима и защищает фактическую отправку; обратное включение не забирает существующие диалоги у сотрудников. Помощь, анализ и расшифровка сохраняют собственные условия и не получают скрытого провайдера при отсутствии агента.

- R-18. По SPEC-0037/ADR-0038 агент может запускать явно разрешённые сервисные действия и сценарии, включая создание, изменение и удаление внешних данных. Они входят в существующий runtime и общий бюджет хода без второго бесконечного цикла; долгие операции возвращают фактическое состояние и продолжаются фоном. Перед каждым эффектом проверяются актуальные разрешения/управление диалогом; завершение не разрешает поздний ответ после отзыва ИИ. Режим самостоятельного выполнения либо подтверждения сотрудником задаётся на операции/сценарии, без общего запрета записи. Сохраняются псевдонимизация, явный выбор провайдера и старые настройки HTTP/MCP/навыков; миграция не расширяет доступ. UI новых действий реализуется по лично принятому baseline SPEC-0037 от 22.10.2026. Карточка агента и редактор сценария показывают одно разрешение агент–действие/сценарий; изменение параметров подтверждения относится к текущему запросу, не меняет определение сценария. Мобильное подтверждение не скрывает значимые параметры. Обновление контекста модели со следующего ответа не отменяет проверку текущего разрешения перед каждым эффектом.

- R-19. Сценарий SPEC-0040 может первым инициировать штатный AI-ход только после серверного согласия/формы, без фиктивной реплики клиента. Задание отдельно от недоверенного data; сохраняются язык/псевдонимизация/очередь/политика. Первый клиентский текст, закрытие или перехват подавляют запоздалый ответ.

- R-20. Планируемый режим external по SPEC-0041/ADR-0041 заменяет только самостоятельное исполнение ответа. Внешний агент выбирается через сервисное подключение и externalAgentId; для него не требуются LLM/модель/embeddings/tool-loop Chatballs, встроенные поля R-1–R-4/R-13–R-18 не управляют логикой сервиса и не экспортируются автоматически. Сохраняются исходный builtin, статус/группа/подключения, очередь и защита управления. Готовый текст не пересказывается моделью. Согласованные исходные данные передаются через отдельную доверенную границу; кастомные поля — отдельным типизированным customer.customFields replace-снимком по разделу «Кастомные поля клиента» контракта SPEC-0041, с WEB-источником и ID определения, явными разрешениями, очисткой текущего контекста и без обратной записи; встроенная LLM сохраняет SPEC-0022. Помощь/анализ/речь не переключаются на сервис автоматически. Асинхронность, инициатива, сроки, идемпотентность и handoff определены SPEC-0041; UI требует своего принятого baseline. Переключение версии исполнения аннулирует старые запросы и не переносит внешнюю память иному агенту.

## Out of scope

Версии и релизы конфигурации агента; выбор агента клиентом; автоматическое распределение диалогов по сотрудникам.
